# KEV 배차 정책 결정 항목 (팀 회의용)

작성일: 2026-10-21
최종 결정 반영: 2026-10-23

## 목적

KEV 배차가 맞게 골랐는지 판정하려면 먼저 "어떤 로봇이 정답인지"를 팀이 정해야 합니다. 이 문서는 회의에서 정할 항목과 각 항목의 현재 코드 동작, 선택지, 추천안을 정리합니다. 합의된 내용은 결정 칸과 아래 확정 사항에 반영합니다.

현재 구현 상태 요약(확정 정책 적용 전):

- 기존 알고리즘 배차는 배터리, 거리를 보지 않고 정렬된 후보 중 첫 번째 로봇을 고릅니다.
- 기존 V3 실험 지시문은 배터리 우선이었습니다. 현재 배차 지시문은 코드가 안전·ETA 후보군을 먼저 확정한 뒤 KEV가 보조 정보를 비교하도록 변경되었습니다.
- 현재 KEV 입력에는 배터리·노드 정보와 코드가 계산한 픽업 거리, 픽업 ETA, 최단 ETA와의 차이, ETA 후보군 정보가 들어갑니다. 작업량과 작업 후 예상 배터리는 아직 들어가지 않습니다.
- 코드에는 실측 전 임시 전압 하한(11.2V)이 있습니다. 실제 로봇은 `battery_state.voltage`의 최근 60초 최저값(연결이 끊기면 기록 초기화), 시뮬레이션은 가상 전압으로 판단하며, 전압을 모르는 로봇도 배차에서 제외합니다. 실측 하한과 Pi 저전압 검사는 아직 없습니다.

### 확정 사항 (2026-10-23)

- 반드시 지켜야 하는 조건과 정확하게 계산할 수 있는 값은 코드가 처리합니다.
- 배차 우선순위 2번은 **픽업 ETA 우선, 배터리는 최소 하한 조건으로 사용**하는 추천안으로 확정했습니다.
- 코드는 후보 검증과 제외, 거리·ETA 계산, 배터리 하한 적용, 확정적 동률 처리를 담당합니다.
- 코드가 ETA 차이가 충분히 큰 후보의 우선순위를 확정하고, KEV는 ETA가 팀이 정한 근소 차이 범위 안에 있는 후보들 사이에서 작업량·상태 등 추가 조건을 판단합니다.
- KEV는 코드가 만든 유효 후보와 계산값을 입력받아, 위 근소 ETA 후보군 중 한 대를 선택합니다.
- 현재 배차 지시문은 ETA 재정렬과 배터리 안전 판단을 KEV에 맡기지 않도록 변경되었습니다. 실제 로봇 적용 전 ETA 속도는 실측 평균 속도로 설정해야 합니다.
- A′/D-3 결과는 배터리 조건을 KEV가 반영할 수 있는지 확인한 실험으로 유지합니다. ETA 우선 최종 정책 검증은 별도 시나리오로 진행합니다.

### 배터리 하한 관련 기존 기록

- `experiment_data/*/trials.csv`의 `battery_percent` 열은 5개 실험 모두 비어 있어, percentage와 전압의 대응 관계나 주문 1건당 percentage 소모량을 계산할 수 없습니다.
- ArUco 정렬 런 120회 중 `battery_min_v`가 기록된 105회의 범위는 10.97V~12.33V입니다. 가장 낮은 10.97V에서도 정렬 성공 사례가 있었습니다.
- 실패 런의 전압은 11.23V~11.56V였지만 같은 전압대의 성공 런도 있어, 현재 데이터만으로 전압과 실패의 인과관계를 판단할 수 없습니다.
- 10월 8일 기록에는 12.31V→11.54V(43분), 12.39V→12.00V(19분)의 소모 사례가 있으나, 주행 조건이 통제된 배터리 소모율 실험은 아닙니다.
- robot3은 11.2V~11.7V에서도 Pi 저전압이 런 시간의 최대 60%를 차지했고 라이다 스캔이 감소했습니다. 기록상 배터리 잔량보다 전원 보드나 케이블 문제 가능성이 더 큽니다.
- robot2도 12.15V에서 Pi 저전압이 발생했습니다. 따라서 정지 상태 전압이나 배터리 잔량만으로 배차 안전성을 판정하기 어렵습니다.
- 기존 기록만으로 `10.5V까지 사용 가능` 또는 `30% 미만 제외`를 우리 로봇의 안전 기준으로 확정할 수 없습니다.
- robot3·robot1에서 OpenCR 응답 끊김이나 리셋이 있었고 배터리 교체 후 해결됐지만, 문제 시점의 전압은 기록되지 않았습니다. 전압이 실제로 문제를 일으킨 지점은 아직 한 번도 측정되지 않았습니다.

임시 기준 11.2V의 근거: 전압이 기록된 105회 중 11.2V 미만은 18회(대부분 robot1), 11.0V 미만은 2회뿐입니다. 이보다 낮은 구간은 성공 사례는 있지만 표본이 적어 검증된 범위로 보기 어렵습니다. robot3는 이 구간 데이터가 거의 없습니다. 실측으로 하한을 정하면 이 임시 기준을 대체합니다.

출처 파일은 모두 `Logistics_AMR/docs/` 아래에 있습니다. `battery_min_v`의 측정 방법(측정 주기, 부하 중 측정 여부)은 문서에 정의되어 있지 않습니다.

따라서 배터리 하한은 다음 순서로 정합니다.

1. 실제 로봇에서 `battery_state.voltage`와 `battery_state.percentage`를 동시에 기록하고 percentage 단위가 0~1인지 0~100인지 확인합니다.
2. 정지 상태 값뿐 아니라 주행 중 최저 전압과 `vcgencmd get_throttled`의 Pi 저전압 발생 여부를 함께 기록합니다.
3. 로봇별 전원 계통 차이를 확인하고, 전원 문제가 처음 나타나는 지점에서 안전 여유를 둔 하한을 정합니다.
4. 데이터가 충분하면 percentage 기준과 전압 기준을 비교하고, 필요하면 로봇별 하한 또는 전압·저전압 상태를 결합한 조건을 적용합니다.

## 3. 코드 규칙과 KEV 판단 조건 분리

반드시 지켜야 하는 조건은 코드가 후보에서 제외합니다. 거리, ETA처럼 계산식이 명확한 값도 코드가 계산합니다. KEV는 코드가 제공한 유효 후보와 계산값을 바탕으로 정책에 따라 후보 중 한 대를 선택합니다.

| 조건 | 코드 역할 | KEV 역할 | 현재 구현 여부 |
|---|---|---|---|
| 연결 여부 | 연결되지 않은 로봇 제외 | 없음 | 구현됨(`available_robots()`) |
| 다른 주문 처리 여부 | busy 로봇 제외 | 없음 | 구현됨(busy 목록) |
| 위치, 점유 정보 유효성 | 값 검증 후 유효하지 않은 로봇 제외 | 없음 | 구현됨 |
| 오류, 정지 상태 | 운행할 수 없는 로봇 제외 | 없음 | 구현됨(IDLE/복귀 상태만 후보) |
| 재시도 시 직전 실패 로봇 제외 | 다른 후보가 있으면 직전 실패 로봇 제외 | 없음 | 구현됨 |
| 최소 배터리 | 실측으로 정한 percentage·전압 하한과 Pi 저전압 상태를 검사해 부적합 로봇 제외 | 없음 | 임시 전압 하한 구현됨: 최근 60초 최저 전압이 11.2V 미만이면 `low_battery`, 전압을 모르면 `battery_unknown`으로 제외(`FMS_MIN_DISPATCH_BATTERY_VOLTAGE`, `FMS_BATTERY_VOLTAGE_WINDOW_S`). Pi 저전압 검사와 실측 하한은 미구현 |
| 적재 용량 | 수량·무게·부피 한도 검사 및 필요 시 주문 분할 | 분할된 유효 배차안 중 선택 가능 | 현재는 수량 5개 제한만 있음 |
| 픽업 거리 | route graph 최단 거리 계산 | 계산하지 않음 | 구현됨. 후보별 `pickup_distance_m` 입력 제공 |
| 픽업 ETA | 거리와 속도로 ETA 계산. 최단 ETA와 설정된 근소 차이 범위 안의 후보군을 확정 | 계산하지 않음 | 구현됨. 현재 코드·실험 기준 2초. 운영값은 재검토 예정 |
| 작업 후 예상 배터리 | 거리와 소모율로 예상값 계산 | 근소 ETA 후보군 안에서 우선순위에 따라 비교 | 미구현. 항목 10 결정 전까지 사용 보류 |
| 최근 작업량 | 정해진 기간의 배차 횟수 또는 이동 거리 집계 | 근소 ETA 후보군 안에서 우선순위에 따라 비교 | 미구현. 항목 4 결정 후 구현 |
| IDLE / RETURNING 상태 | 상태를 명확한 값으로 분류해 입력 | 근소 ETA 후보군 안에서 항목 3의 우선순위에 따라 비교 | 상태값은 입력에 있음(`returning`), 세부 정책 미확정 |
| 완전 동률 | `robot_id` 등 확정 규칙으로 최종 처리 | 완전 동률 해소를 맡기지 않음 | 일부 구현. 임시 기준선·fallback은 robot_id 오름차순으로 확정. KEV 선택 결과의 동률 판정은 미구현 |
| 조건 충돌 시 선택 | ETA 차이가 근소한 후보군과 정규화된 계산값 제공 | 후보군 안에서 배터리·작업량·상태 등 후순위 조건을 비교해 선택 | 일부 구현. 근소 ETA 후보군과 상태·현재 배터리는 입력됨. 작업 후 예상 배터리·최근 작업량은 미입력 |

## 4. 초기 정책 방향

```text
1. 코드 필수 조건 통과 (연결, 미배정, 위치 유효, 최소 배터리, 직전 실패 로봇 제외)
2. 코드가 각 후보의 route graph 최단 거리와 픽업 ETA 계산
3. 코드가 최단 ETA보다 팀이 정한 범위만큼 더 긴 후보를 제외
4. ETA가 근소하게 차이나는 후보군만 KEV에 전달
5. KEV가 후보군 안에서 작업 후 예상 배터리, 최근 작업량, IDLE / RETURNING 상태를 정해진 우선순위로 비교
6. KEV 선택 실패 또는 완전 동률이면 코드가 정한 fallback 규칙으로 확정
```

2번의 ETA 우선 원칙은 확정되었습니다. ETA 근소 차이 범위는 현재 코드와 KEV 비교 실험에서 `2초`이며, 실제 로봇 ETA 측정과 실험 결과를 확인한 뒤 운영 정책값으로 재검토합니다. 최소 배터리 수치 등 나머지 값은 추가 결정이 필요합니다. 여기서 ETA 근소 차이 범위는 최단 ETA보다 몇 초 더 긴 후보까지 KEV 비교 후보군에 남길지 정하는 값입니다. 이 범위를 벗어난 후보는 KEV에 전달하지 않습니다. 같은 순서를 코드로 구현한 규칙 알고리즘을 비교 기준선으로 둡니다. 현재는 작업량·작업 후 예상 배터리 정책 확정 전의 임시 기준선(`IDLE·비복귀 → 현재 배터리 높은 순 → robot_id 오름차순`)이 구현되어 있고, KEV 오류·cooldown 시 fallback에도 이 기준선을 씁니다. KEV는 배차 전체가 아니라 근소 ETA 후보군에서의 선택만 비교합니다. 안전 후보 전체를 KEV에 전달하는 방식은 사용하지 않습니다.

| 구간 | 처리 및 비교 대상 |
|---|---|
| ETA 차이가 큰 경우 | 코드가 즉시 선택. KEV 비교 대상 아님 |
| ETA가 근소한 경우 | 규칙 알고리즘 선택 vs KEV 선택 |
| KEV 오류·timeout·cooldown | 같은 근소 ETA 후보군 안에서 코드 fallback |
| 전체 운영 결과 | 현재 알고리즘, 규칙 알고리즘, 보호형 KEV의 완료 시간·편중·fallback 비율 비교 |

상황 요약, 모니터링 판단 등 배차 외 KEV 활용은 이 실험과 섞지 않고 별도 범위로 다룹니다.

비교할 때는 현재 알고리즘에 배터리나 ETA 기능이 없다는 점을 분리해서 기록합니다. 단순히 선택 결과만 비교하지 않고 평균 픽업 ETA, 최소 배터리 위반 횟수, 배차 편중, 처리 시간, fallback 발생률을 함께 측정합니다.

## 5. 회의 후 진행 순서

1. 배터리 voltage·percentage·주행 중 최저 전압·Pi 저전압 여부 수집
2. 측정 결과로 최소 배터리 기준을 정하고, ETA 근소 차이 운영값(현재 실험 기준 2초) 재검토, RETURNING 우선순위, 작업량 기준 등 남은 결정 칸 확정
3. 실측 하한으로 전압 기준 갱신(임시 11.2V 구현됨), Pi 저전압 검사, 후보 검증, 완전 동률 처리 등 코드 규칙 구현
4. 완료: route graph 거리와 픽업 ETA 계산 함수를 구현하고, ETA 후보군만 KEV 입력 schema에 전달
5. 완료: 배터리 우선 V3 지시문을 ETA 후보군 보조 판단 지시문으로 변경
6. 실제 로봇의 ETA 속도를 실측 평균 속도로 설정하고 ETA 근소 차이 운영값을 재검토
7. 같은 정책을 코드로 구현한 규칙 알고리즘 기준선 작성
8. ETA 단일 조건 실험 → 배터리 하한 실험 → 조건 충돌 실험 → 세 방식 비교
9. 장애, fallback, 회귀 재검증 후 실제 로봇 검증

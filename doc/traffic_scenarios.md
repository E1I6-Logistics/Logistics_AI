# 관제 시나리오 사용 안내

2026-10-22 정리. 10월 21일 목록 정리에 거리·시간 입력 보완을 반영했다. **화면에는 9개만 표시한다. 예전·중복 시험 14개는 원본과 API·CLI 식별자를 보존하고 개발용으로 보관했다.** 원래 21개에 같은 조건의 비교 2개를 추가했으므로 파일에는 총 23개가 있다.

## 먼저 구분할 것

2026-10-24 사용자 결정: **화면의 9개는 그대로 유지하고 설명만 보완한다.** 이름·실행 조건·판단 방식·보관 상태는 변경하지 않는다.

| --- | --- |

일반 주문에서 사용하는 ‘KEV가 전략 검토 순서를 제안하는 방식’과, 별도 배치에서 ‘만들어진 완성 조정안 중 선택하는 방식’은 같은 판단 흐름이 아니다. 화면의 묶음 설명과 각 항목의 ‘이 시험에서 확인하는 것’을 함께 읽는다.

최근의 **동일 주문표 12건 비교는 별도 실행 도구로 관리**한다. 화면의 무작위 자동 공급을 두 번 실행한다고 동일 입력의 알고리즘·AI 비교가 되는 것은 아니다. 비교 도구·결과·입력 구성은 [전체 결과와 시험 범위](experiments/order-traffic-results-and-coverage-20261024.md)에 정리했다.

**여러 대가 비켜주고 통과·복귀하는 새 기능은 별도 배치 시험까지 구현했다. 일반 주문 처리 중 막힘을 자동 감지해 여러 대를 비켜주는 기능으로 연결한 상태는 아니다.** 일반 주문의 기존 교통제어와 새 실험을 혼동하지 않는다. 시뮬에서는 실제 아루코·OMX 작업을 실행하지 않는다. 실기체 도착 처리 수정·새 양보 연결은 뒤로 미뤘다.

- **일반 주문**부터 보면 끊김 없이 주문이 처리되는 흐름을 볼 수 있다. 새 다중 양보가 연결됐다는 증거로 보지 않는다.
- **경로 연결 확인**은 경로 생성 A*(기본)/KEV와 교통조정 연결을 확인한다. 전체 일반 주문 시험과 다르다.
- **교통조정만 시험**은 세 대 통과 순서, 앞 로봇 먼저 이동과 우회, 정차 로봇 양보와 우회, 이동 불가 시 무출발을 각각 확인한다.
- **여러 대 양보 비교**는 같은 배치를 코드만 / KEV만 / KEV 후 코드 보완으로 나눠 본다.

‘움직일 방법이 없으면 출발하지 않기’는 **이번 입력의 허용 경로로 해결하지 못하면 이동 0단계**를 확인하는 시험이다. 길이 비기를 기다렸다가 자동 재출발하는 시험이나 지도 전체의 해결 불가능 판정이 아니다.

## 여러 대 양보 세 항목의 비교 조건

공통 배치는 **R1=N3→N0, R2=N11 정차, R3=N10 정차**다. R2는 N6, R3는 N8로 비켜줄 수 있고, 양보한 로봇의 원래 자리 복귀까지 완성해야 한다. 의도적으로 만든 정지 상태이며 연속 주문에서 자연 발생한 장애로 표현하지 않는다.

| 방식 | 검사 순서 선택 | 모델 한도 뒤 처리 |
| --- | --- | --- |
| 코드만 | 관계 정보에 따른 코드 규칙 | 모델 호출 없음 |
| KEV만 | 같은 관계 정보에서 KEV 추천 | 모델 제안 한도면 미해결 종료·이동하지 않음 |
| KEV 후 코드 보완 | 먼저 KEV 추천 | 정상적인 모델 호출 횟수 한도 뒤 코드가 남은 순서를 검토 |

‘KEV만’도 경로 생성·예약 검사·도착 확인은 코드를 사용한다. **검사 순서 선택을 코드가 이어받지 않는다는 뜻**이다. 모델 통신 오류·잘못된 응답·전체 시간 초과를 정상 호출 한도처럼 취급해 코드로 숨기지 않는다.

세 항목은 지도·시작 상태·목적지·허용 동작·분기 보관이 같고, **검사 128회 / 계획 8단계 / 계획 시간 10초**를 공통 적용한다. KEV를 쓰는 두 항목은 **제안 8회 / 개별 응답 2초**도 같다. 검사 시간에는 모델 통신을 포함한다. 첫 완성 계획을 찾는 탐색이며 평균 도착 시간의 전역 최적 계획을 보장하지 않는다.

2026-10-22부터 세 항목 모두 `recovery_motion_estimates=true`다. 지도 좌표로 계산한 이동 거리·시간, 누적 이동 시간과 남은 경로의 낙관적인 도착 시간 계산을 코드와 KEV에 같은 값으로 제공한다. 목록의 ‘거리·이동 시간 정보 포함’과 제안 기록의 ‘이동 예상’ 문구로 확인한다. 전체 계획이 완성되기 전의 계산값이며 실제 도착 예정 시각이나 예약 허가가 아니다. 속도는 0.2m/s이고 회전·예약 정지·KEV 응답 시간은 제외한다.

[전후 비교 결과](experiments/kev-mapf-recovery-motion-input-20261022.md): 두 대 양보는 KEV 단독으로 여전히 3회 모두 미해결이었다. 우회가 있는 별도 한 상황에서는 같은 최종 경로를 찾는 모델 호출이 5회에서 1회로 줄었다. 전체 성능이 좋아졌다는 결론은 아직 없다.

기존 `dfs_two_robot_yield`와 `guided_two_robot_yield`는 예전 탐색 방식이므로 현재 공정 비교에서 제외했다. 새 두 항목과 기존 혼합 항목이 같은 관계 정보·분기 보관을 쓴다. 결과는 해결 여부 → 계획 시간·검사·모델 호출 → 이동·복귀 시간 순서로 함께 본다. 이번 정리는 KEV가 더 우수하다는 결론이 아니다.

## 보관한 14개와 이유

## 실행 방법

1. [관제](http://100.81.82.30:5173/)에서 **시뮬·AI**를 선택한다. 진행 중 주문·복귀·예약이 있으면 먼저 끝나야 별도 배치 시험을 실행할 수 있다.
2. 지도 위 목록에서 시험을 고른다. 새 배치 시험은 시작 시 가상 좌표를 지정 배치로 맞춘다.
3. **테스트 실행**을 누른다. 다음 단계는 이전 단계 도착을 확인한 뒤 시작한다.
4. 진행·완료 문구와 예상·실제 시간, 여러 대 양보 항목에서는 KEV 제안 기록을 확인한다.
5. 일반 주문 공급은 **주문 공급 중지**로 새 등록만 멈춘다. 접수 주문은 계속 처리된다. 별도 이동 시험의 긴급 중단은 기존 비상정지를 사용한다.

일반 주문 공급은 시뮬·AI에서 실행한다. 나머지 새 교통조정 시험은 시뮬·AI/알고리즘에서 실행할 수 있고 실기체 모드는 거부한다. AI 모드여도 시험용 고정 경로를 쓰는 항목은 경로 생성용 KEV 호출이 없다. 목적에 따라 경로 생성과 교통조정 KEV 호출을 구분한다.

기존 이름의 CLI도 유지한다. 예:

```bash
PYTHONNOUSERSITE=1 ~/venv/robot/bin/python tests/traffic_scenarios.py dependency_code_two_robot_yield
PYTHONNOUSERSITE=1 ~/venv/robot/bin/python tests/traffic_scenarios.py dependency_kev_two_robot_yield
PYTHONNOUSERSITE=1 ~/venv/robot/bin/python tests/traffic_scenarios.py guided_deferred_two_robot_yield
```

CLI는 서버의 현재 모드를 따른다. 보관한 예전 이름도 직접 지정하면 실행 가능하다. 일부 기존 관제 시험에는 실기체 실행 기능도 있으므로 별도 이름을 CLI로 실행할 때 현재 모드를 반드시 확인한다. CLI를 닫아도 접수된 시험은 서버에서 계속된다. 새 여러 대 양보 시험을 실기체에 연결하지 않았다.

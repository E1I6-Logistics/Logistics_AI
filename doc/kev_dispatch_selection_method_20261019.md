# KEV 배차 선택 방식 기록

작성일: 2026-10-19

## 핵심 정리

현재 운영상 배차 방식은 **기존 알고리즘 배차**와 **KEV 배차** 두 가지입니다.

KEV 내부 선택은 조건별 가중치를 코드에서 합산하는 점수제가 아니라, 후보 로봇별 선택 확률을 계산하고 가장 높은 확률의 로봇을 고르는 **확률 기반 Choice 방식**입니다.

```text
현재 운영 배차 방식
  1. 기존 알고리즘 배차
  2. KEV 배차

KEV 내부 선택 방식
  후보별 선택 확률 계산
    -> 가장 높은 확률의 후보 선택(argmax)
```

## 기존 알고리즘 배차

- 배차 가능한 로봇 후보를 기존 규칙에 따라 정렬합니다.
- 재시도 주문이면 가능한 경우 직전 로봇을 뒤로 보냅니다.
- 조건에 맞는 첫 번째 후보를 선택합니다.
- 배터리, 거리 등의 가중 점수를 합산하는 방식은 아닙니다.

관련 함수:

- `backend/app/services/order_manager.py::_select_robot_by_algorithm()`

## KEV 배차

1. `available_robots()`가 연결 상태, 작업 상태, 점유 상태 등을 확인해 안전한 후보만 남깁니다.
2. 재시도 주문이고 다른 후보가 있으면 `last_robot_id`를 제외합니다.
3. 후보가 한 대이면 KEV를 호출하지 않고 해당 로봇을 선택합니다.
4. 후보가 두 대 이상이면 KEV의 `select_choice()`를 호출합니다.
5. KEV가 반환한 후보별 확률 중 가장 높은 값을 가진 로봇을 선택합니다.
6. KEV 호출이 실패하면 기존 알고리즘 배차로 fallback합니다.

관련 함수:

- `backend/app/services/order_manager.py::_select_robot_with_kev()`
- `backend/app/services/route_selector/kev_selector.py::select_choice()`

## A′ 실험 예시

| 후보 | KEV 선택 확률 |
|---|---:|
| robot1 | 0.1405 |
| robot2 | 0.2961 |
| robot3 | 0.5634 |

가장 높은 확률을 받은 robot3이 최종 선택됐습니다.

```text
choice = argmax(후보별 선택 확률)
```

## Score 방식과의 차이

`KevSelector`에는 `evaluate_score()`도 구현돼 있지만, 현재 로봇 배차에서는 사용하지 않습니다.

| 구분 | 배차 사용 여부 | 역할 |
|---|---|---|
| 기존 알고리즘 | 사용 | 정렬된 후보 중 첫 번째 로봇 선택 |
| KEV Choice | 사용 | 후보별 선택 확률 중 최댓값 선택 |
| KEV Score | 미사용 | 대상을 점수 또는 단계로 평가 |
| KEV NOUL | 미사용 | 불확실성 관련 평가 |

## 프로젝트 정리용 문장

현재 FMS는 기존 규칙 기반 알고리즘과 KEV 기반 배차를 선택적으로 사용할 수 있습니다. KEV 배차는 사람이 정의한 가중 점수를 합산하는 방식이 아니라, 사전에 안전 조건을 통과한 후보 로봇을 입력받아 각 후보의 선택 확률을 계산하고 가장 높은 확률의 로봇을 선택하는 Choice 방식으로 구현했습니다. KEV 장애 시에는 기존 알고리즘으로 자동 전환해 주문 처리를 유지합니다.

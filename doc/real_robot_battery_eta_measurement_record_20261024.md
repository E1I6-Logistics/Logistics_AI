# 실제 로봇 주행 전압·ETA 측정 기록표 - 2026-10-24

## 1. 목적

한 번의 실제 주행에서 두 가지를 함께 기록한다.

- **전압:** 주행 중 최저 전압을 모아 배차 전압 하한(현재 임시 11.2V, `FMS_MIN_DISPATCH_BATTERY_VOLTAGE`)을 정한다.
- **ETA:** 코드 ETA와 실제 픽업 도착 시간의 차이를 모아 ETA 근소 차이 범위(현재 실험값 2초, `KEV_DISPATCH_ETA_TIE_SECONDS`)를 정한다.

배터리는 다른 팀과 공유하고 충전된 것을 바로 쓰므로 배터리 이름 대신 **날짜·시각·로봇·시작 전압**으로 회차를 구분한다.

## 2. 코드 ETA 기준

코드 ETA는 route graph(`test.geojson`) 최단 거리 ÷ `KEV_DISPATCH_ETA_SPEED_MPS`(0.2 m/s)이다.

- ArUco 정렬, 예약 대기, 출발 지연은 포함하지 않는다.
- **ArUco 정렬은 기존 측정값을 근거로 ETA에서 뺀다.** 10/9~10/11 성공 71회 평균 47.3초, 중앙값 43초, 범위 18~101초(`Logistics_AMR/docs/aruco_alignment_team_guide_20261015.md`, 원자료 `aruco_align_runs_*.csv`의 `duration_s`). 픽업 ETA(2.6~12.2초)보다 훨씬 길고 같은 로봇·노드에서도 수십 초씩 흔들려, 더해도 2초 판단이 정확해지지 않는다. 후보들은 같은 픽업 노드에서 똑같이 정렬하므로 ETA는 픽업 노드 도착까지만 비교한다.
- 기존 측정은 여러 코드 버전이 섞였고 10/11 이후 N3·N4 벽이 옮겨졌다. 정렬 시간을 주문 처리 시간이나 예약 시간 같은 운영값으로 쓸 때는 다시 측정한다.
- 예약 계산용 `FMS_REAL_NAVIGATION_SPEED_MPS`(0.15 m/s)와는 별개 값이다.
- 근소 차이 판단은 후보 사이의 ETA 차이로 하므로, 실제 시간과의 절대 오차보다 **로봇·출발 노드 사이에서 오차가 얼마나 다른지**가 중요하다.

| 출발 노드 | → N5 (A/B) 거리 | → N5 ETA | → N6 (C/D) 거리 | → N6 ETA |
| --- | ---: | ---: | ---: | ---: |
| N0 (robot1 충전) | 1.653 m | 8.26초 | 2.438 m | 12.19초 |
| N1 (robot2 충전) | 1.356 m | 6.78초 | 2.142 m | 10.71초 |
| N2 (robot3 충전) | 1.502 m | 7.51초 | 2.287 m | 11.44초 |
| N3 (작업대) | 1.299 m | 6.49초 | 0.513 m | 2.57초 |
| N4 (작업대) | 1.608 m | 8.04초 | 0.822 m | 4.11초 |

route graph나 ETA 속도를 바꾸면 이 표를 다시 계산한다.

## 3. 측정 절차

1. FMS를 real 모드로 켠다. 브라우저는 열지 않아도 된다(백엔드가 2초마다 연결을 갱신한다).
2. 로봇 bringup과 Zenoh 브리지를 켜고 `curl -s localhost:8000/api/robots`로 등록과 `battery_voltage`를 확인한다.
3. 상태 기록을 시작한다. 0.5초마다 상태·현재 노드·전압이 CSV(`logs/`, git 제외)에 쌓인다.

   ```bash
   bash tools/diagnostics/record_robot_status.sh
   ```

4. 측정할 로봇 한 대만 배차 가능하게 두고 주문을 넣는다. 다른 로봇과의 예약 대기가 섞이면 비고에 적는다.
5. 회차마다 아래 표를 채운다. 시각은 CSV의 `time`(소수 초)을 쓴다. 백엔드 로그 시각은 초 단위라 2초 판단에는 거칠다.
   - **출발:** 해당 로봇의 `status`가 IDLE에서 바뀐 첫 행. `logs/backend.log`의 `[REAL NAV ROUTE SEND]`로 교차 확인한다.
   - **픽업 도착:** `current_node`가 픽업 노드가 된 첫 행. API에는 노드가 숫자로 나온다(N5 → `5`, N6 → `6`). `[REAL NAV ARRIVAL] target=`으로 교차 확인한다.
   - **ArUco(선택):** `[ROS ARUCO] Goal 전송`과 `[ROS ARUCO] 완료` 로그 시각(초 단위). 측정 항목이 아니라, 현재 설치 버전·벽 위치에서 기존 값과 비슷한지 보는 참고용이다.
6. 주행이 끝나면 Pi에서 저전압 이력을 확인한다. `0x0`이 아니면 비고에 값을 적는다.

   ```bash
   vcgencmd get_throttled
   ```

- **실제 주행:** 픽업 도착 시각 − 출발 시각. ArUco 정렬 시간은 포함하지 않는다.

## 6. 판단 기준

- **ETA 근소 차이 범위:** 대기 없는 회차에서 로봇·출발 노드별 오차 평균이 서로 얼마나 다른지 본다. 그 차이가 2초보다 크면 2초 안의 ETA 순위는 실제 도착 순서를 보장하지 못하므로 범위를 넓히는 근거가 되고, 차이가 작으면 2초를 유지하거나 줄일 수 있다.
- **ArUco 정렬:** ETA에 넣지 않는다(2절). 다만 기존 자료에서 N6 중앙값이 robot3 약 58초, robot2 약 30초로 달랐다(표본 1~6회). 선택 칸 기록에서도 로봇별 차이가 계속되면 "누가 먼저 픽업을 끝내나" 관점에서 따로 검토한다.
- **전압 하한:** 주행 중 최저 전압과 `get_throttled` 저전압 기록이 처음 나타난 전압을 함께 보고 11.2V를 유지할지 정한다. 결정은 `kev_dispatch_policy_decisions_20261021.md`에 반영한다.

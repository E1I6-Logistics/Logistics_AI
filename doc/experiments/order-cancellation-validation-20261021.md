# 일반 주문 취소 후 뒤 주문 재개 확인

2026-10-21. **배차 전 주문을 취소해도 다른 주문은 계속 처리됐고, N5에서 작업 중인 앞 주문을 취소해도 뒤의 두 주문은 정상 완료됐다.** 취소한 로봇도 홈으로 돌아왔다. 기존 실행 코드 수정 없이 현재 관제의 시뮬레이션에서 확인했다.

## 어떤 상황을 만들었나

같은 픽업대 N5를 방문하는 A 1개 주문을 4건 등록했다. 이름은 `CANCEL-CHECK-20261021-1`부터 `4`까지다. 처음 세 건은 R1·R2·R3에 배차되고, 네 번째는 배차 대기 상태로 남았다.

```text
1번 주문 / R1: N5로 이동 → 픽업 작업 중 취소 → 홈 N0 복귀
2번 주문 / R2: N5 차례 대기 → N5가 비워지면 이동 → 작업 완료·복귀
3번 주문 / R3: N5 차례 대기 → R2가 N5를 떠나면 이동 → 작업 완료·복귀
4번 주문:      배차 대기 중 취소 → 로봇 배정 없이 종료
```

관제의 기존 주문 등록·취소 API를 사용했다. 별도 가상 로봇을 만든 시험이 아니므로 [관제 화면](http://100.81.82.30:5173/)의 주문 이력에서 이 네 건을 볼 수 있다. 취소는 이력을 삭제하는 동작이 아니라 주문 상태를 `CANCELLED`로 바꾸는 동작이다.

## 실제로 관측한 순서

시각은 첫 시험 주문 등록 직전부터의 경과 시간이며, API에서 처음 관측한 값이다.

| 시각 | 관측 내용 |
| --- | --- |
| 약 0.42초 | 4번 주문이 미배차 `PENDING`인 상태에서 취소. 로봇 배정·복귀 요청 없음 |
| 약 8.65초 | R1이 N5에서 픽업 작업 중인 것을 확인하고 1번 주문 취소 |
| 약 8.97초 | 1번 주문은 취소 상태를 유지하고, R1 복귀 상태는 `RETURNING` |
| 약 9.11초 | N5가 비워진 뒤 R2의 N5 이동 요청이 적용됨 |
| 약 9.32초 | R2가 실제 통로를 이동 중인 것을 확인. R1은 아직 홈 복귀 중 |
| 약 16.23초 | R2가 N5에서 픽업 작업 시작 |
| 약 17.41초 | 취소한 R1 홈 복귀 완료: `recovery_status=RETURNED` |
| 약 17.72초 | R2는 작업대로 이동하고 R3는 N5로 이동 |
| 약 25.74초 | 2번 주문 작업 완료 |
| 약 34.81초 | 3번 주문 작업 완료 |
| 약 45.06초 | 뒤 주문의 마지막 로봇까지 복귀 완료 |

핵심은 **취소한 R1의 전체 복귀를 기다리지 않고, N5가 실제로 비워지면 R2가 이어받았다는 것**이다. R1이 아직 N5를 점유한 관측 상태에서는 R2에 N5 이동 목표가 없었다.

## 왜 이렇게 동작하나

1. 미배차 주문 취소는 해당 주문 상태만 바꾼다. 담당 로봇이 없으므로 복귀를 만들지 않는다.
2. 진행 주문을 취소하면 그 주문을 현재 픽업 차례에서 제외하고 로봇을 정지·복귀시킨다.
3. 주문이 취소됐어도 로봇의 실제 점유는 즉시 사라지지 않는다. 뒤 로봇은 실제 N5 점유가 해제될 때까지 기다린다.
4. 이후 뒤 주문의 이동은 기존 교통조정·최신 예약 검사로 진행한다.

시뮬·AI, **A* 경로 생성 + KEV 교통조정 선택** 설정으로 실행했다. 뒤 주문 처리 중 실제 KEV 요청·응답은 1회였고 오류 기록은 없었다. 취소 후 홈 복귀는 기존의 **알고리즘 복귀 기능**을 사용한다. KEV가 취소 복구 계획을 새로 만들었다는 결과는 아니다.

## 결과와 보존 확인

- 시험 주문: **2건 완료, 2건 의도한 취소**. 주문 실패·복귀 오류 없음.
- 실제 점유 상태 관측 **278회**, 노드·물리 통로 중복 점유 관측 없음.
- 기존 완료 주문 138건은 내용까지 그대로 유지했다. 최종 이력은 완료 140건·취소 2건, 총 142건이다.
- 시험 시작은 홈 N0·N1·N2로 맞추고, 종료 후 원래 N0·N11·N10의 위치·자세·배터리와 시뮬·AI·KEV 설정을 복원했다.
- 종료 후 로봇은 모두 대기 상태이고, 픽업 대기열과 작업대도 비어 있다.
- 실행에 사용한 주요 코드 사본과 해시를 보관하고, 종료 후 원본 코드가 바뀌지 않은 것을 확인했다.

이것은 한 번의 취소 흐름 확인이다. 약 0.075초 대기와 API 조회 시간이 합쳐진 표본 관측이며 모든 순간의 안전이나 실기체 동작을 증명하지 않는다. 전체 자동 검사 묶음을 이번에 다시 실행한 결과와도 구분한다.

**이 최초 시험에 포함하지 않은 것:** 통로를 주행하는 도중 취소, 작업대 작업 도중 취소, 연결 끊김, 취소 복귀 경로가 장시간 막히는 상황, 실제 적재된 물품의 반납·정산. 특히 물리적으로 물건을 집은 뒤 취소할 때의 물품 처리는 별도 운영 규칙이 필요하다. 이번 시험은 로봇 이동과 주문 대기열의 연속성만 확인했다.

같은 날 [후속 시험](order-cancellation-followup-20261021.md)에서 픽업·작업대 이동 중 취소, 픽업 차례 대기 중 취소, 작업대 작업 중 취소와 새 주문 재배차까지 확인했다. 위 수치는 최초 시험 당시의 결과로 보존한다.

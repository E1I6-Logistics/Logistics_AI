# 연속 주문 결과 분석: 처음 달라진 것은 6번 주문의 배차

2026-10-23. [직전 부하 시험](order-traffic-load-comparison-20261023.md)의 저장 로그를 분석했다. 새 운행·모델 호출·관제 명령은 없고 원래 운행 파일은 보존했다.

## 쉽게 보는 결론

혼합·빠른 접수에서 새 KEV 방식이 더 빨랐던 결과는 그대로다. 다만 **KEV가 더 좋은 전략을 골라서 빨라졌다고 설명할 근거는 아직 부족하다.** 네 비교 모두 처음 배차 로봇이 달라진 주문은 6번이었고, 그때부터 출발 위치와 후속 경로가 달라졌다.

앞서 로봇·작업대 배정을 묶어 집계하면서 작업대도 바뀐 것처럼 설명한 부분을 정정한다. **12회 운행의 작업대는 모두 N3으로 같았다.** 달라진 것은 배차 로봇과 경로이며, 이번 시간 차이를 작업대 변경의 효과로 설명하지 않는다.

## 1. 어디서 처음 달라졌나

A/B 집중의 두 주문표는 배차 로봇·작업대·적용 경로가 같았다. 새 KEV 방식은 마지막 복귀까지 약 2~3초 더 걸렸다.

두 픽업대 방문과 주문 몰아서 접수는 두 주문표 모두 다음 순서로 갈라졌다.

```text
앞선 주문들: 적용 경로와 배차 로봇은 같음, 진행 시각에는 작은 차이
                         ↓
6번 주문을 배차할 순간의 로봇 상태가 달라짐
   ├─ 코드 시험: 홈 N2의 R3에 배차
   │              → N2 → N9 → N7 → N5
   └─ 새 KEV 시험: 작업대 N3 쪽의 R2에 배차
                  → N3 → N11 → N7 → N5
                         ↓
이후 배차 순서·로봇 위치·예약·이동 경로가 함께 달라짐
```

| 상황·주문표 | 코드: 6번 주문 배차 관측 | 새 KEV: 6번 주문 배차 관측 | 6번 주문 작업 완료까지 단축 |
| --- | --- | --- | ---: |
| 두 픽업대 방문·42 | 약 47.7초, R3 | 약 46.5초, R2 | 약 4.10초 |
| 주문 몰아서 접수·42 | 약 47.8초, R3 | 약 46.4초, R2 | 약 4.03초 |
| 두 픽업대 방문·137 | 약 47.7초, R3 | 약 46.5초, R2 | 약 4.32초 |
| 주문 몰아서 접수·137 | 약 47.9초, R3 | 약 46.3초, R2 | 약 4.11초 |

배차 시각은 0.2초 안팎의 관측에서 처음 확인한 값이다. 정확한 사건 시각은 직전 관측과 해당 관측 사이에 있다. 주문과 로봇은 별도 HTTP 요청으로 읽었으므로 한 표본의 두 응답을 완전히 동시에 저장한 상태로 취급하지 않는다.

대표인 두 픽업대 방문·42에서, 6번 주문의 적용 경로에 기록된 예상 시간은 코드 약 9.90초, 새 KEV 약 6.49초였다. 서로 다른 출발 위치·예약 상태에서 계산한 값이다. 동일한 상태에서 KEV가 코드를 이긴 선택으로 해석하지 않는다.

6번 이전 다섯 주문의 접수→작업 완료 시간 차이는 네 비교에서 주문별 약 ±0.41초 안이었다. 6번부터 새 KEV 시험에서 약 4초의 단축이 관측되고 후속 주문에도 차이가 이어졌다. 마지막 주문의 단축은 약 7.1~12.8초였다. 이것은 차이가 나타난 순서와 관측 결과이며, 첫 배차 차이 하나가 전체 이득을 전부 만들었다는 인과관계 증명은 아니다.

## 2. 왜 R2를 다시 배차할 수 있었나

현재 배차는 [order_dispatcher.py](../../backend/app/services/order_dispatcher.py)의 후보 조건과 [order_manager.py](../../backend/app/services/order_manager.py)의 대기 주문 처리 규칙을 따른다. KEV가 배차 로봇을 선택하는 구조가 아니다.

- 주문 작업을 마치고 홈으로 복귀 중인 로봇도 **노드에 있고 엣지 위가 아니면** 다음 배차 후보가 될 수 있다.
- 다만 먼저 접수된 주문이 같은 픽업대를 아직 요청 중이면, 복귀 로봇을 새 주문에 붙잡아 두지 않도록 배차를 미룬다.
- 이 조건은 현재 주문 단계·현재 점유·복귀 경로 유무에 따라 변한다.

대표 로그에서 코드 시험의 R2는 4번 주문 뒤 N3을 떠나 엣지로 이동했다. 6번 배차 시점에는 후보가 되지 못했고, 홈에 도착한 R3가 선택됐다. 새 KEV 시험에서는 R2의 복귀 경로를 검토하는 동안 앞선 R1이 N5에서 N6으로 이동했고, R2가 N3에 있는 시점에 6번 주문이 배차됐다. 원래 복귀 계획은 취소되고 새 픽업 이동으로 연결됐다.

네 비교에서 R2의 해당 복귀 경로는 두 방식 모두 `N3→N11→N7→N9→N1`로 같았다. 이 경로의 조정 처리 시간은 코드 약 0.002~0.003초, 새 KEV 약 0.185~0.209초였다. 새 KEV의 모델 응답 대기는 약 0.182~0.205초였다.

**모델 응답을 기다린 시간과 비동기 갱신 시점의 차이가 배차 가능 순간을 바꿨다는 설명과 로그가 부합한다.** 이 저장 로그 분석 시점에는 대조 시험이 없어 모델 지연만이 원인이라고 확정하지 않았다. 후속 [세 조건 대조](order-traffic-ranking-ablation-20261023.md)에서 고정 순서＋평균 대기로도 빠른 배차·완료 흐름이 재현됐다. 다만 요청별 지연을 정확히 맞춘 반복 실험은 아니므로 단독 인과효과까지 확정하지 않는다.

## 3. 이번에 KEV가 탐색을 줄였나

줄였다는 근거는 없었다. 새 KEV 방식의 기록은 다음과 같다.

| 확인 항목 | 결과 |
| --- | ---: |
| 적용 이동 | 264회 |
| 모델 호출 | 116회 |
| 모든 준비 전략 ID에 시도 기록이 있는 이동 | 264/264회 |
| 경로 호출 한도·시간 한도로 건너뛴 전략 | 0회 |
| 코드의 최소 예상 시간 규칙과 최종 선택 일치 | 264/264회 |
| 예약 불가 뒤 전체 재시도한 이동 | 0회 |

407개 전략 시도 기록 중 VALID는 330건, 경로 생성 불가는 58건, 예약 불가는 19건이었다. 같은 물리 경로에 다른 전략 이름이 붙은 기록도 있으므로 서로 다른 경로 407개나 유효 계획 330개라는 뜻은 아니다.

이 입력 크기와 한도에서는 준비한 전략을 모두 검토했다. KEV의 순서 제안으로 일부 전략만 검사해 계산을 아낀 경우는 없었다. 최종 선택은 처음부터 코드가 맡았으므로 최소 시간 규칙과의 일치율을 KEV 판단 정확도라고 부르지 않는다.

동일한 후보·동일한 예상값을 고정하면 후보 표시 순서가 달라도 현재 최종 선택 규칙은 같다. 실제 주행 중에는 전략을 검토하는 동안 다른 로봇도 움직여 상태가 바뀔 수 있다. 이번 기록만으로 전략 순서의 모든 영향을 없다고 단정하지는 않는다.

## 4. 지금의 판단과 다음 검증

현재 구조로 이번 주문표를 모두 처리한 기능 결과는 유효하다. 혼합·빠른 접수에서 관측된 속도 향상도 유효하다. 그러나 **AI가 더 좋은 교통 전략을 제안한 효과**와 **판단 대기 중 달라진 시점·배차의 효과**는 아직 분리하지 못했다.

이 분석에서 제안한 **모델만 고정 전략 순서로 바꾸는 대조군**은 이후 [별도 시뮬 시험](order-traffic-ranking-ablation-20261023.md)으로 실행했다. 새 KEV·고정 순서·고정 순서＋평균 대기의 12건씩을 모두 완료했고, 평균 대기를 넣은 고정 순서가 새 KEV와 비슷한 시간에 끝났다. 관제에 대조 옵션이나 인공 대기를 추가하지 않았다. 이 문서의 오프라인 분석과 후속 실제 운행 기록은 구분해 보존한다.

기존 배차 조건을 지금 바꾸지는 않는다. 향후에는 노드 통과 순간과 갱신 시점에 따라 복귀 로봇의 재배차가 크게 달라지는지도 별도로 검토할 수 있다. 그 문제를 먼저 발견했다고 해서 KEV 성능 개선으로 기록하지 않는다.

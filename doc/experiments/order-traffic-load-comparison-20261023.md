# 연속 주문 부하 비교: 코드와 새 KEV

2026-10-23. 기존 12건 한 차례 점검을 이어서, 주문이 몰리는 조건에서도 처리가 이어지는지 확인한다. jhlee 추가 비교는 보류한다. 이 문서의 시험은 시뮬 전용이며 실제 로봇 연결을 다루지 않는다.

## 목적과 조건

현재의 **기존 주행 계획 유지 + 새 이동 요청 조정** 구조를 유지한다. 코드 방식과 새 KEV 전략 순서 방식에 동일한 주문·지도·시작 위치·주행 속도·작업 시간을 제공한다. 새로운 교통조정 알고리즘이나 화면 기능을 추가하는 작업은 아니다.

| 상황 | 주문 내용 | 접수 시점 |
| --- | --- | --- |
| A·B 집중 | 한 픽업대를 방문하는 주문 12건 | 처음 3건, 이후 5초 간격 |
| 두 픽업대 혼합 | 모든 주문이 A/B와 C/D를 함께 포함, 12건 | 처음 3건, 이후 5초 간격 |
| 빠른 공급 | 혼합 상황과 물품·수량·순서가 같음 | 처음 3건, 이후 0.5초 간격 |

각 상황은 seed 42·137의 두 주문표로 확인한다. 주문당 총수량은 1~5개이며 두 픽업대 주문은 최소 2개다. 첫 주문표는 코드→새 KEV, 두 번째는 새 KEV→코드 순서로 실행한다. 순서 교대만으로 시간 변동의 영향을 모두 없앴다고 보지는 않는다. 총 계획은 **6개 주문표 × 2방식 = 12회 운행 시험**, 방식별 접수 주문 총 72건이다.

주문표를 실행 전에 파일로 고정하고 두 방식에 같은 파일을 전달한다. 각 실행마다 빈 주문표·홈 위치의 별도 시뮬 프로세스를 사용한다. 8033 포트를 사용하며 화면용 8000 서버는 모드·주문·시나리오 조회만 한다. 동일한 8012 KEV 서버를 순차 공유한다. 경로는 기존 A*, 속도 0.2m/s, 작업 1.5초, 예약 마진 0.2초, 출발 대기 한도 60초다.

일반 자동 공급의 PENDING 상한은 이 시험에 적용하지 않는다. 정해진 시각에 일반 주문 API로 접수해 빠른 공급 조건에서 대기열이 쌓이는지를 확인한다. 마지막 접수 후 새 주문 없이 작업·복귀가 끝날 때까지 기다린다. 정책별 관측 한도는 300초다.

## 확인할 값

- 주문 완료·복귀 완료·최종 홈 위치, 실패와 복귀 오류
- 접수 응답부터 작업 완료까지 평균·최장 주문 시간, 접수부터 배차까지 대기 시간
- 마지막 작업 완료 시각과 최종 복귀 시각, 최대 PENDING·동시 진행 건수
- 로봇별 WAITING 누적·최장 연속 관측 시간
- 모델 요청·응답·오류, 응답 시간 합계, 적용 경로와 선택 출처
- 약 0.2초 간격의 노드·물리 엣지 중복 점유 관측
- 주문표·시작 상태·지도·설정 일치, 접수 지연, 소스·기존 화면 상태 보존

WAITING은 로봇 상태를 관측한 시간이므로 교통조정 때문에 발생한 대기만을 뜻하지 않는다. 접수부터 완료까지 시간에는 주문 대기열·픽업 작업·이동이 포함된다. 일회 배치의 물품/분 값을 지속 물류 처리량으로 해석하지 않는다. 표본 점유 확인은 관측 사이의 충돌까지 없었다는 증명이 아니다.

모델 요청 카운터에는 방식 비교마다 공통 준비 요청 1회를 포함해 대조한다. 이 준비 요청은 주문 교통조정 호출 수와 분리한다. KEV를 다른 화면이나 도구에서도 호출하면 카운터 대조가 틀릴 수 있으므로 원문을 확인한다.

## 결과

**계획한 12회 운행을 모두 완료했다.** 같은 주문 72건을 두 방식에 각각 넣어 총 144건·물품 합계 436개를 작업·홈 복귀까지 완료했다. 코드·새 KEV 모두 주문 실패·복귀 오류가 없었다. 추가 재시험이나 실패 이력 삭제 없이 처음 계획한 실행을 끝냈다.

### 어떻게 해석할까

이번 범위에서는 현재 구조로 주문 대기열을 처리하고 복귀까지 이어갈 수 있었다. A/B 집중은 코드가 두 번 모두 조금 빨랐고, 혼합·빠른 공급은 새 KEV가 두 주문표 모두 빨랐다. 모든 상황에서 KEV가 더 좋다고 결론 내리지는 않는다.

A/B 집중은 주문별 적용 경로와 로봇 배정이 두 방식에서 같았다. 혼합·빠른 공급은 적용 경로가 달랐고, 배차 로봇이 다른 주문은 각각 7·6·6·6건 있었다. **후속으로 로봇·작업대를 분리해 확인한 결과 작업대는 모든 운행에서 N3으로 같았다. 작업대 변경이 시간 차이를 만든 것은 아니다.** 이 결과에는 모델 호출 지연과 이동·예약 시점 변화, 그 뒤의 배차 변화가 함께 들어 있다. 전체 연결 방식의 관측 성능 차이는 확인했지만, KEV의 전략 순서 판단 자체가 개선을 만들었다고 분리해 증명한 것은 아니다.

가장 오래 배차를 기다린 주문은 약 105.67초였고, 가장 긴 주문 처리 시간은 약 126.89초였다. 배차 전 PENDING 대기와, 배차 뒤 경로를 요청하며 기다리는 교통조정 대기 한도 60초는 서로 다르다. 특정 주문이 계속 밀리지 않도록 하는 보호 규칙까지 새로 구현한 시험은 아니다.

특히 0.5초 간격 공급은 유한한 12건을 접수한 뒤 공급이 끝난 조건이다. 이런 속도로 무기한 공급해도 대기열이 늘지 않는다는 결과는 아니다. 후속 [저장 로그 분기 분석](order-traffic-load-review-20261023.md)에서 혼합·빠른 공급 모두 6번 주문의 배차가 첫 분기였음을 확인했다. KEV 시험은 N3의 R2, 코드 시험은 홈 N2의 R3에 배차했다. 모델 대기와 갱신 시점 변화에 부합하는 흐름이며 지연의 단독 효과까지 확정하지 않는다. 새 KEV 이동 264회 모두 준비된 전략을 끝까지 시도해 이번 탐색 절감 근거도 없었다. 이번 결과만을 근거로 운영 기본값이나 실기체 정책은 변경하지 않았다.

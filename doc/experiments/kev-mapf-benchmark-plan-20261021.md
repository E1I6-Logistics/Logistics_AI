# KEV가 교통조정에 도움이 되는지 확인할 시험 초안

2026-10-21. **우리 지도에 맞춘 이동 상황 5개와 출발 금지 대조 상황 1개를 준비했다. 코드로 입력·실행 가능성을 확인했으며, 이 새 묶음의 실제 KEV 비교는 아직 하지 않았다.** 운영에서 생길 수 있는 상황인지 검토한 뒤 비교 입력을 확정한다.

시험 입력 준비는 일반 주문·실기체 동작을 바꾸지 않는다. 후속 운영 검토에서는 기존 관제의 자동 공급으로 시뮬레이션 주문 12건을 추가해 자연 정지를 관찰했다. 새 시나리오 추가·백엔드 재시작·강제 위치 변경·실기체 명령은 하지 않았다. 아래 운영 조건과 관찰 결과를 함께 읽는다.

## 목표와 이번 시험의 범위

전체 목표는 **주문이 계속 들어와도 로봇이 서로 길을 막아 오래 멈추지 않고 물류를 처리하는 것**이다.

그 목표를 위해 이번에 확인할 작은 질문은 다음과 같다.

> 같은 위치·목적지·허용 이동·제한 시간에서, KEV가 검토 순서를 추천하면 코드 규칙만 사용하는 것보다 좋은 완성 계획을 더 빨리 찾는가?

현재 일반 주문은 새로 출발할 로봇 한 대의 경로 후보를 선택한다. 이 시험은 여러 로봇의 양보·통과 순서 탐색을 확인하는 **별도 정지 상태 실험**이다. 일반 주문이 진행되는 동안 기존 주행을 변경하거나 막힘을 자동 복구하는 연결은 아직 하지 않는다.

현재 탐색기는 **처음 찾은 실행 가능한 완성 계획**에서 끝난다. 최소 평균 도착 시간의 계획을 보장하는 탐색이 아니다. 검토 순서가 계획을 찾는 시간과 찾은 계획의 이동 시간에 어떤 영향을 주는지 측정한다.

## 실제 지도와 공통 가정

`routes/test.geojson`의 노드·엣지를 그대로 사용한다. 아래는 연결 관계를 간략히 그린 것이며 실제 거리 비율은 아니다. 각 연결은 양방향이고, 노드와 물리 통로에는 동시에 한 대만 허용한다.

```text
N0 ── N10 ── N8 ── N12 ── N4
       │      │      │
N1 ── N9 ─── N7 ── N11 ── N3
     ╱        │      │
   N2         N5 ─── N6
```

- R1·R2·R3는 시험 시작 시 노드에서 정지해 있고, 주문·이동·예약이 진행 중이지 않다.
- R1은 작업대 N3에서 다음 픽업대 또는 홈으로 이동한다. R1을 다른 로봇의 홈 N1에서 출발시키지 않는다.
- 양보 로봇은 물건을 집거나 작업대 작업을 수행 중이지 않고 이동시켜도 된다고 가정한다.
- 경로는 미리 제공한다. 양쪽 방식은 같은 진행·우회·양보·복귀 동작을 사용한다.
- 양보는 로봇마다 한 번까지, 완성 계획은 원래 목적지 도착과 양보 로봇의 복귀까지 포함한다.
- 노드가 지도에 있다는 것만으로 실제 대기 위치로 허용되는 것은 아니다. 사용자는 N5·N6가 비어 있고 집기 작업 중이 아닐 때 임시 양보 위치로 쓰는 것을 허용했다. 양보 중에는 해당 노드·이동 경로의 점유와 예약을 유지하고 새 픽업 요청과 조정해야 한다. N8 등의 실제 정차 적합성은 별도 확인이 필요하다.
- 양보 도착도 실제 위치·점유를 확인한다. 작업 목적지 완료와 구분해 아루코 정렬·집기 작업을 시작하지 않아야 한다. 기존 실기체 내부 양보에는 이 구분이 있으나 새 KEV 다중 양보와의 실기체 연결은 아직 없다.
- 이번 양보 목적지는 안전하게 정차할 수 있는 허용 노드다. 엣지 중간 정차는 기존 물리 통로 전체를 계속 점유하므로 양보 효과를 보장하지 않는다. 엣지를 세분화한 대기 지점·위치 검증·예약 설계는 별도 확장 범위다.
- 입력의 `wait_allowed_nodes`에는 초기 정차 노드도 포함한다. 이는 기존 정지 상태 입력 계약을 맞추기 위한 것이며, 해당 노드에 장기 주차하는 운영 정책이 확정됐다는 뜻은 아니다.

## 준비한 상황

| 번호 | 쉬운 이름 | 시작 상황과 확인할 판단 | 준비·재사용 |
| --- | --- | --- | --- |
| 1 | 길이 비어 있는 다음 픽업 이동 | R1=N3→N5, R2=N1·R3=N2 대기. 다른 로봇을 움직이지 않고 바로 이동하는가? | 새 입력. 정상 동작 대조 |
| 2 | 앞 로봇이 먼저 빠지면 통과 | R1=N3→N0. 길목의 R2=N11→N6. R2가 자기 목적지로 먼저 가면 R1이 통과한다. | 새 입력. 진행 순서 |
| 3 | 한 대가 비켜주기 또는 다른 길로 가기 | R1=N3→N0, R2=N7 정차. R2가 N5로 비켜주는 방법과 R1이 N12·N8을 지나는 우회를 둘 다 허용한다. | 새 배치. 기존 동작 종류 재사용 |
| 4 | 두 대가 비켜줘야 복귀 | R1=N3→N0, R2=N11·R3=N10 정차. R2→N6, R3→N8 양보 후 R1이 통과한다. | 이전에 시험한 N3 복귀 배치 재사용 |
| 5 | 양보할 자리부터 비워줘야 하는 경우 | R1=N3→N0, R2=N11, R3=N8. R2의 허용 양보 위치가 N8이므로 먼저 R3가 N5로 비켜줘야 한다. | 새 입력. 대기 위치 제한의 현실성 확인 필요 |
| 6 | 필요한 양보 경로가 입력에 없는 경우 | 4번에서 R3의 양보·복귀 동작을 입력에서 뺀다. 완성 계획 없이 출발하면 안 된다. | 이전 입력 부족 시험 재사용. 성능 시험과 구분 |

1번에는 검토할 동작이 하나뿐이므로 KEV를 호출하지 않는 것이 정상이다. 이 상황을 AI가 개선한 사례로 집계하지 않는다.

2번은 다른 로봇이 자기 목적지로 먼저 이동하는 것이다. 3~5번은 원래 그 자리에 머무를 로봇도 잠깐 이동시키고 되돌리는 시험이다. 두 의미를 구분한다.

5번의 의존 관계는 다음과 같다.

```text
R1이 N11을 지나야 함
 → R2가 N11에서 비켜야 함
 → 이번 입력에서 R2의 양보 위치는 N8
 → N8에 있는 R3가 먼저 N5로 비켜야 함

허용 경로에서 가능한 한 순서:
R3: N8 → N7 → N5
R2: N11 → N12 → N8
R1: N3 → N11 → N7 → N9 → N10 → N0
R2: N8 → N12 → N11
R3: N5 → N7 → N8
```

실제로 R2가 N6로 바로 비킬 수 있다면 5번과 같은 의존이 필요하지 않을 수 있다. **AI를 유리하게 보이게 하려고 우회·양보 선택을 숨기지 않는다.** 제한의 운영상 이유가 없다면 시험을 수정하거나 제거한다. 제공한 동작만으로 풀 수 없다는 결과를 지도 전체의 해결 불가능으로 해석하지 않는다.

## 먼저 확인한 내용: 코드 준비 검사

관제와 분리된 가상 로봇에서 관계 기반 코드 탐색과 BFS를 각각 실행했다. 총 6상황×2방식=12번이다. KEV 요청은 0회다.

| 상황 | 관계 코드 검사 횟수 | 관계 코드 결과 | BFS가 찾은 첫 계획 단계 수 |
| --- | ---: | --- | ---: |
| 1. 정상 다음 픽업 | 1 | 이동 완료 | 1 |
| 2. 앞 로봇 먼저 이동 | 2 | 두 로봇 이동 완료 | 2 |
| 3. 한 대 양보 또는 우회 | 1 | 우회 계획으로 완료 | 1 |
| 4. 두 대 양보 | 5 | 통과·복귀 완료 | 5 |
| 5. 양보 자리부터 비우기 | 5 | 통과·복귀 완료 | 5 |
| 6. 필요한 동작 부족 | 5 | 허용한 동작을 검토한 뒤 미해결·이동 0단계 | 해당 없음 |

두 코드 방식 모두 예상한 결과를 냈고 가상 실행의 점유 검사에서 중복 점유는 없었다. **이 결과는 입력을 준비할 수 있다는 확인이다. KEV 성능 개선이나 실제 주문 처리량 검증 결과가 아니다.** BFS는 단계 수 순으로 탐색하므로 이번 첫 계획의 단계 수를 대조하는 데만 사용한다. 이동 시간의 전역 최적성을 주장하지 않는다.

## 실제 비교를 진행할 때의 조건 초안

| 방식 | 검토 순서를 고르는 주체 | 결과 해석 |
| --- | --- | --- |
| A. 코드 기준 | 기존 관계 정보 코드 규칙 | 비교 기준. 단순 요청순 코드만을 약한 기준으로 쓰지 않음 |
| B. KEV 추천 | KEV가 다음 검토 동작을 선택 | 모델 제안 한도 내 성과. 한도에 도달하면 중지하고 미해결로 기록 |
| C. KEV 추천 후 코드 보완 | KEV 한도 후 A의 코드 규칙이 이어받음 | 실제 사용할 수 있는 혼합 방식. 성공 전체를 KEV 단독 성과로 세지 않음 |

공통으로 같은 지도·입력·이동 동작·분기 보관·예약 검사·가상 실행기를 사용한다. 전체 한도는 **검사 128회, 이동 8단계, 계획 10초**다. B·C는 추가로 모델 제안 최대 8회, 개별 응답 최대 2초를 적용하고 전체 10초 한도에도 포함한다. 이미 진행 중인 동기 검사 한 번은 강제 중단하지 않으며, 한도 뒤 결과로 출발하지 않는 기존 규칙을 유지한다.

같은 입력이라도 모델 제안에 따라 중간 상태와 남은 시간이 달라진다. 두 방식의 실제 요청 문자열이 항상 같다는 의미는 아니다. 시작 입력·허용 동작·원래 제약의 해시를 보관하고, 코드에만 제공한 사후 정답이나 KEV에만 제공한 추가 양보 동작은 두지 않는다.

우선 각 상황을 세 번씩 실행하고 방식의 실행 순서를 바꾼다. 6상황×3방식×3반복이면 **54번의 탐색 실행**이다. 이 숫자는 모델 호출 횟수가 아니며 1번처럼 모델 호출이 없는 실행도 포함된다. 최종 규모는 상황 검토 후 확정한다. 로봇 ID·표시 순서 변경, 새로운 배치의 검증은 별도 묶음으로 남기고 결과를 본 뒤 유리한 상황만 골라 합치지 않는다.

## 무엇으로 좋아졌다고 판단하나

먼저 실행 가능한 1~5번의 **완성 계획 해결률**을 보고, 6번은 **부분 계획을 실행하지 않았는지** 별도로 보고한다. 입력 부족 시험의 안전한 정지를 이동 실패율에 섞지 않는다.

| 지표 | 정의·읽는 방법 |
| --- | --- |
| 해결 여부 | 제한 안에 원래 목적지·양보 로봇 복귀를 만족하는 완성 계획을 찾았는가 |
| 실제 계획 시간 | 입력 처리·관계 계산·예약 검사·모델 통신을 포함한 실제 경과 시간 |
| 검사 횟수·모델 호출 | 적을수록 무조건 좋은 것이 아님. 미해결로 조기 종료한 경우도 함께 표시 |
| 가상 실행 평균 도착 시간 | 처음 이동 요청이 있던 로봇들의 이번 목적지 도착 평균. 양보만 하는 로봇은 평균에서 제외하고 복귀 완료는 따로 확인 |
| 모든 양보·복귀 완료 시간 | 처음 이동 요청 없는 로봇의 복귀까지 포함한 가상 실행 시간 |
| 계획 시간 + 가상 평균 도착 시간 | 판단 비용을 합친 참고 계산값. 서로 다른 시계를 합친 합성 지표이므로 실기체 또는 실제 관제의 관측 완료 시간으로 부르지 않음 |
| 중복 점유·미완료 | 노드·물리 통로 중복 점유, 미해결·시간 초과·모델 오류를 숨기지 않고 보고 |

성공한 실행만 골라 전체 평균을 주장하지 않는다. 해결률과 실패 사유를 먼저 제시하고, 같은 상황에서 함께 성공한 실행의 시간 비교는 별도로 표시한다. 작은 반복 표본은 통계적 우수성이나 4대 이상 확장 성능의 증명이 아니다.

KEV는 코드보다 계획을 빨리 찾거나, 같은 한도에서 더 많은 상황을 해결하거나, 계획 시간이 늘어도 가상 이동의 개선으로 전체 이득이 생기는 경우를 보여야 한다. 현재 관계 코드가 이미 1~5회 검사로 해결하므로 이 묶음에서 KEV의 이점을 찾기 어려울 수 있다. 모델이 불리하다는 이유로 기준 코드를 약하게 바꾸지 않는다.

## 운영 검토와 실제 도착 처리

사용자는 **픽업대 N5·N6가 비어 있고 물건 집기 작업이 없으면 잠깐 비켜서는 자리로 사용 가능**하다고 답했다. 단, 실기체의 도착 후 아루코 동작을 구분해야 한다.

```text
작업 목적 이동 → 위치·도착 확인 → 아루코 정렬 → 주문 작업
양보 목적 이동 → 위치·도착 확인 → 노드 점유·대기 → 후속 이동
```

도착 판정을 없애는 방식이 아니다. 실제로 어디까지 도착했는지는 두 경우 모두 확인한다. 구분할 것은 도착 뒤 시작하는 작업이다.

- `ros_gateway.on_navigation_result()`의 일반 최종 목적지가 N3·N4·N5·N6이면 아루코 정렬을 요청한다. 주문이 없다는 이유만으로 정렬을 생략하지 않는다. OMX 작업 여부는 정렬 뒤 별도로 판단한다.
- 기존 `RealNavigation._send()`는 내부 양보 중인 이동을 최종 작업 도착(`final`)으로 표시하지 않는다. `_check_arrival()`은 실제 도착을 확인하되 `final`일 때만 최종 완료 콜백을 호출한다. 기존 내부 양보에는 작업 도착과 분리하는 구조가 이미 있다.
- 새 KEV 다중 양보 실험은 관제와 분리된 시뮬레이션이다. 실기체 연결 시 기존 구분을 유지하고 양보 도착이 최종 작업 콜백으로 전달되지 않는지 검증해야 한다. 일반 목적지 이동 함수를 그대로 호출하는 것만으로 이 조건을 만족한다고 보지 않는다.
- 복귀용 `RETURN`을 양보 목적 표시 대신 사용하는 임시 처리는 하지 않는다. 복귀는 자체 후속 처리 의미가 있다.

외부 ROS 명령을 모의 객체로 바꾼 분리 검사에서 일반 N5 목적지 완료는 아루코 요청을 만들었고, 내부 도착 처리의 `final=False`는 위치·점유 확인 후 작업 완료 콜백을 호출하지 않았다. **실기체 전체 양보·복귀를 시험한 결과는 아니다.**

## 연속 주문에서 자연스럽게 생기는가

사용자는 길목 정지가 가능할 것으로 보지만 실제 발생은 확정하지 않았고, 연속 주문 관찰 또는 의도적 시험 배치를 허용했다.

기존 자동 공급으로 시뮬레이션 AI 주문 **12건·물품 33개**를 추가했다. A* 경로와 기존 일반 주문 KEV 선택을 사용했으며 새 다중 양보 탐색은 호출하지 않았다. 5초 간격, 초기 3건, PENDING 상한 3건, 무작위 시드 42다. 모든 주문 완료와 세 로봇의 홈 IDLE까지 약 **114.39초**, 기록 186회에서 중복 점유·주문 실패는 보고되지 않았다. 기존 주문 272건 내용도 바뀌지 않았다.

이 관찰에서는 N7·N10·N11 및 N8·N9·N12를 점유한 정지 장면이 수집되지 않았다. 따라서 1초 이상 정지하거나, 주문·경로·이동 요청이 없는 IDLE 방해 로봇도 확인하지 못했다. 기록 간격이 약 0.6초이므로 짧은 정지를 놓칠 수 있고, 12건에서 없었다고 실제 운영에서도 발생하지 않는다고 결론 내리지 않는다. 이 결과는 실기체 아루코·양보 검증이 아니다.

일반 주문의 경로·예약이 남은 대기를 별도 정지 상태 실험의 이동 가능한 IDLE로 바꾸면 안 된다. 현 입력 어댑터는 진행 작업·경로·이동 요청·예약·보호 자원이 없는 상태를 요구한다. 이번 로그에는 로봇별 상세 예약도 없으므로 정지 사진만으로 전체 입력 적합성을 판정하지 않는다.

3~5번은 **의도적으로 준비한 정지 상태 시험**으로 유지한다. 자연 발생 운영 장애나 연속 주문 자동 복구로 표현하지 않는다. 특히 5번의 ‘R2 양보 위치는 N8’ 제한에는 여전히 운영상 이유가 필요하다. 이유 없이 대표 운영 시험으로 확정하거나 AI에 유리하게 선택지를 숨기지 않는다.

[도착 구분·연속 주문 관찰 기록](kev-mapf-arrival-and-stop-review-20261021.md)에 근거 파일과 한계를 정리했다. 이후 비교 입력 확정 → KEV 비교 → 결과 검토 → 일반 주문·실기체 연결 여부 판단 순서로 진행한다.

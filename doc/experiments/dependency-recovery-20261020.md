# 관계 정보와 계획 분기 되돌아가기 실험

공유 범위: 이 문서의 과거 진단·수동 시험 도구와 `logs/` 원문은 기능 공유에서 제외하고 로컬에 보관한다. 아래의 관련 재현 명령은 해당 보관 자료가 있을 때의 실행 예시다.

2026-10-20. 사용자가 새 방식을 구현한 뒤 설명을 듣고 판단하기로 했으므로, 기존 설정을 유지한 **별도 선택 방식**으로 구현했다. 작업 전 복원 지점도 만들었다.

후속 [미룬 순서 보관·한도 뒤 코드 보완](deferred-recovery-20261020.md)에서는 유효한 분기를 보존하도록 수정하고 관제에 별도 항목을 추가해 완료했다. 아래 표는 그 수정 전의 결과로 보존한다.

## 무엇을 만들었나

기존 입력의 경로·현재 가상 위치·동작 단계로 다음 관계를 코드가 정리한다.

```text
R1은 N3 → N11 → N7 → N9 → N10 → N0로 이동해야 한다.
R2는 N11에 있다. R1이 지나려면 R2가 비켜야 한다.
R3는 N10에 있다. R1이 지나려면 R3도 비켜야 한다.
R3가 N8로 비켰다가 R1 통과 전에 N10으로 복귀하면 다시 길을 막는다.
```

이 정보를 KEV와 코드 비교 방식에 동일하게 준다. 이동 후보를 완전 탐색한 정답·검사 통과 결과로 교체하거나, KEV에게만 후보를 제거해 주지는 않는다.

| 새 입력 | 계산 방법과 의미 |
| --- | --- |
| `remaining_supplied_paths` | 현재 단계에서 원래 목적지까지 갈 수 있도록 제공된 경로. 우회·양보 후 복귀 경로도 반영 |
| `must_visit_nodes` | 위 경로들의 공통 노드. 주어진 어느 경로를 써도 지나야 하는 위치 |
| `current_other_occupants` | 이번 후보 경로에 현재 다른 로봇이 있는 위치 |
| `clears_required_nodes` | 이번 이동이 다른 로봇에게 필요한 위치를 비우는 관계 |
| `finishes_on_required_nodes` | 이번 이동 후 더 움직일 수 없는 로봇이 다른 로봇의 필수 경로에 정차하는 관계 |
| `irreversible_blockers` | 현재 분기에서 더 움직일 수 없는 로봇이 다른 로봇의 필수 경로를 막는 관계 |

이것은 **제공된 경로와 로봇별 1회 양보 제한** 아래의 관계다. 지도 전체에서 가능한 모든 경로의 필수 노드를 증명한 것이 아니다. 우회 경로가 있으면 그것도 공통 노드 계산에 반영하므로, 원래 경로에 있다는 이유만으로 필수 노드라고 하지 않는다. 관계 계산은 예약 검사나 완성 계획 탐색을 호출하지 않는다.

## ‘되돌아가기’의 뜻

새 방식에서는 중간 상태에서 `BACKTRACK`을 고를 수 있다.

```text
복사한 상태에서 R3 양보 → R3 조기 복귀를 검토
  ↓
이 분기는 R1 통과를 막는다.
  ↓ BACKTRACK
아직 실행하지 않은 이 분기를 버리고 다른 순서를 검토
```

실제 로봇을 후진시키거나 이미 실행한 주행을 취소하는 명령이 아니다. 완성 계획을 찾고 최종 검사까지 통과하기 전에는 로봇에 새 이동을 실행하지 않는다.

모델이 너무 일찍 돌아가면 해결 가능한 분기도 포기할 수 있다. 따라서 새 방식의 `BRANCHES_ABANDONED`는 **모델이 일부 분기를 포기한 뒤 남은 목록이 끝남**을 뜻하며, 해법이 없다는 증명이 아니다. 제안 8회 한도는 `MODEL_CALL_LIMIT`으로 따로 표시한다. 두 경우 모두 완성 계획이 없으면 이동을 실행하지 않는다.

새 두 방식 모두 전역 방문 상태 제거를 사용하지 않는다. 한 분기를 중간에 포기한 뒤 다른 순서에서 같은 가상 위치에 도달할 수 있으므로, 기존 방문 기록만으로 그 가능성을 제외하지 않기 위해서다. 검사·단계·시간 한도는 그대로 적용한다.

## 비교한 네 방식

| 설정 | 동작 선택 | 관계 정보 | 중간 분기 포기 |
| --- | --- | --- | --- |
| `DEPTH_FIRST` | 기존 코드 순서 | 없음 | 기존 방식으로 자식 동작 소진 후 복귀 |
| `KEV_GUIDED` | 기존 KEV 제안 | 기존 상태 입력 | 동일 |
| `DEPENDENCY_DFS` | 관계를 사용하는 단순 코드 규칙 | 제공 | 허용 |
| `KEV_DEPENDENCY` | 새 KEV 제안 | 동일하게 제공 | 동일하게 허용 |

공정한 새 방식 비교는 마지막 두 행이다. 코드 규칙은 현재 경로가 막혔는지, 마지막 정차가 다른 로봇의 필수 위치를 막는지, 누군가의 길을 비우는지로 고른다. 끝까지 탐색한 사후 정답을 사용하지 않는다.

공급 동작·지도·예약 검사·검사 128회·8단계·10초 한도는 동일하다. 모델은 추가로 제안 8회, 개별 응답 2초 한도를 사용한다. 현재 일반 주문은 이 새 설정을 사용하지 않는다. 기존 관제 화면의 시나리오도 그대로다.

## 실제 결과

N3→N0 복귀, 다른 작업대 N4→N0 복귀, 필요한 양보 동작 하나를 제공하지 않은 상황의 세 입력을 사용했다. 상황별 각 방식을 두 번씩 실행했다. 최종 코드 기준 **24회 격리 탐색·가상 실행, 실제 모델 요청 74회**다. 모델 응답을 포함한 실제 계획 시간과 가상 이동 완료 여부를 따로 기록했다.

해결 가능한 두 배치의 결과는 다음과 같다. 각 방식은 배치별 두 번, 합계 네 번이다.

| 방식 | 끝까지 이동·복귀 완료 | 예약 검사 수 | 계획 시간 |
| --- | ---: | ---: | ---: |
| 기존 코드 DFS | 4/4 | 매번 13회 | 약 0.006~0.008초 |
| 기존 KEV | 4/4 | 매번 13회 | 약 0.852~1.032초 |
| 관계 정보 코드 | 4/4 | 매번 5회 | 약 0.003~0.004초 |
| 관계 정보 KEV | 0/4 | N3 각 7회, N4 각 6회 | 약 0.933~0.994초 |

새 KEV의 검사 수가 작다는 이유로 개선됐다고 보면 안 된다. **해결을 완료하지 않고 탐색을 끝냈기 때문에 적은 수**다. N3 시험은 두 번 모두 모델 제안 8회 한도에 도달했다. N4 시험은 두 번 모두 해결 가능한 분기까지 포기했다.

필요한 양보 동작이 없는 상황은 모든 방식에서 미해결이었다. 기존 두 방식은 검사 5회, 관계 코드 2회, 관계 KEV 3회였다. 새 KEV의 경우에도 전체 해법 부재를 증명한 것은 아니다. 완성 계획이 없어 이동하지 않았다는 결과다.

모든 격리 실행에서 노드·물리 엣지 중복 점유 위반은 0회다. 새 KEV 시험은 여섯 실행 모두 이동 0단계였다. 일반 주문·실기체·실행 중인 관제 상태를 대상으로 한 이동 시험이 아니다.

### 왜 새 KEV가 실패했나

기록에서는 여전히 막힌 R1 진행과 R3 조기 복귀를 제안했다. 잘못된 분기에서 돌아가는 경우도 있었지만, **다른 로봇을 비켜주면 해결할 수 있는 상태에서도 돌아가기를 선택**했다. 모델 내부 원인이나 학습 부족 여부를 확정할 수는 없다. 이번 결과는 ‘새 선택권을 주면 더 잘 해결한다’는 가정을 지지하지 않는다.

전체 상태가 바뀌면서 남은 시간 등 입력 값도 달라지므로 반복 실행의 요청이 바이트 단위로 완전히 동일한 것은 아니다. 이 작은 두 배치만으로 다른 지도·모델의 성능을 일반화하지 않는다.

### 채택 여부

**새 KEV 방식은 기본으로 채택하지 않았다.** 새 관계 코드도 실험 설정으로만 남겼다. 일반 주문 처리, 기존 시나리오 선택, 기존 KEV 입력 기본값은 유지했다. 관계 정보와 간단한 코드 규칙의 효과는 확인됐지만, 이 판단에 KEV를 추가한 이점은 확인되지 않았다. 구현을 읽고 사용자와 채택·수정·복원 여부를 판단할 수 있다.

## 이번 작업 전으로 복원하기

복원 지점은 다음 위치다.

`logs/change-snapshots/20261020-195059-before-recovery-relations/`

- `source-before.tar.gz`: 작업 전 소스 247개. 기존 미커밋 수정·추가 파일 포함.
- `before.json`: 당시 파일 해시·권한·HEAD·작업 상태.
- `rollback.json`: 이번 작업에서 바뀐 파일의 전후 해시와 새 파일 목록.
- `restore.py`: 이번 범위만 복원. 그 이후 추가 수정이 있으면 덮어쓰지 않고 중단.

이것은 소스 복원 지점이다. 가상환경·모델 가중치·실행 중인 서버 상태를 복원하는 도구가 아니다. 이번 작업에서는 해당 환경과 서버를 변경하지 않았다.

기본 실행은 복원 목록 미리보기다. 실제 복원은 사용자가 요청할 때 수행한다.

```bash
python3 logs/change-snapshots/20261020-195059-before-recovery-relations/restore.py
```

실제 복원 시에는 같은 명령에 `--apply`를 붙인다. 사용자 요청 전에는 실행하지 않았다. 임시 폴더에서 미리보기·후속 수정 보호·파일 복원·재실행 동작을 검증했다. Git의 전체 초기화를 사용하지 않으며 기존에 진행하던 다른 변경은 보존한다.

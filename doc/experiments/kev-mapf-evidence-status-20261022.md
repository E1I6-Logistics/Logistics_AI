# 무엇이 작동했고, KEV의 효과는 어디까지 확인했나

2026-10-22. 여러 단계 양보 시험의 실패를 일반 물류 전체의 실패로 확대하지 않고, 반대로 일반 주문 완료를 KEV의 성능 개선 증거로 해석하지 않기 위한 정리다.

## 기능 동작과 성능 개선은 다른 질문이다

| 질문 | 현재 근거와 판단 |
| --- | --- |
| 주문을 계속 넣으면 배차·픽업·작업대·완료·복귀가 이어지는가? | 시뮬레이션에서 확인했다. KEV 선택과 코드 선택 모두 연속 주문을 처리했다. |
| 검사된 경로 후보 중 KEV가 고른 경로를 실제 가상 주행기로 실행할 수 있는가? | 연결 동작은 확인했다. 모델이 항상 목표에 맞는 가장 짧은 예상 시간을 고른 것은 아니다. |
| KEV 덕분에 코드보다 물류 처리량이 좋아졌는가? | 일관된 개선을 확인하지 못했다. 기존 소수 비교는 차이가 작거나 실행에 따라 방향이 바뀌었다. |
| 여러 단계 양보 순서를 KEV가 안정적으로 고르는가? | 현 모델·입력·한도에서는 기준 미달이다. 추가 지시문 수정·모델 시험은 중단했다. |
| KEV 경로 생성까지 모두 정상인가? | 아니다. 일부 생성 실패가 이미 있다. 최근 일반 주문 비교는 양쪽 모두 A* 경로를 사용했다. |
| 실제 로봇·장시간 운용까지 검증됐는가? | 이번 결과는 가상 로봇 시험이다. 실기체·장시간 처리량·모든 예외를 보장하지 않는다. |

**‘KEV가 포함된 시스템으로 주문을 처리할 수 있다’는 것과 ‘KEV가 처리량을 개선했다’는 것을 구분한다.** 현재 전체 흐름은 경로·예약·후보 생성·검사·실행을 코드가 담당하고, KEV는 그중 선택에 참여한다. 시스템의 정상 동작을 전부 KEV의 기여로 계산하지 않는다.

## 이전 일반 주문 비교에서 이미 확인한 것

[18건씩 연속 처리 검증](continuous-order-validation-20261021.md): 같은 주문표 18건·57개를 KEV와 코드가 각각 완료했다. 총 36건이며 주문 실패·취소·복귀 오류는 없었다. 노드·물리 엣지의 중복 점유는 1,756회 표본에서 관측하지 않았다.

| 지표 | KEV 선택 | 예상 시간 최소 코드 |
| --- | ---: | ---: |
| 출고 모두 완료 | 약 185.64초 | 약 182.29초 |
| 주문당 평균 완료 | 약 63.22초 | 약 61.82초 |
| 예상 최소 후보 선택 | 19/22회 | 23/23회 |

앞 로봇이 픽업대를 떠나 작업대로 가는 동안 다음 로봇이 같은 픽업대로 이동하는 장면과, 홈 복귀를 끝내기 전 새 주문을 받는 사례도 관측했다. 앞 주문이 모두 끝나야만 다음 로봇이 출발하는 구조가 아니다.

이 한 쌍에서 코드는 약 3.35초 빨랐다. 이전 작은 주문표 비교에서는 한 실행에서 KEV가 빨랐으나 반복 시 차이가 유지되지 않았다. 소수 실행으로 일반 우열을 확정하지 않는다. 같은 주문표라도 선택·주행·예약 시점에 따라 뒤의 후보와 담당 로봇이 달라질 수 있다.

후속 [저장된 일반 주문 선택 분석](general-order-kev-choice-review-20261023.md): 19/22회에는 시간 동률 7회가 포함된다. 시간 차이가 있는 경우는 12/15회 일치이고, 더 먼 길이 대기를 줄여 더 빠른 세 선택은 모두 같은 N1→N5 유형에서 실패했다. 후보의 전체 예상·대기 시간은 실제 요청에 있었고 응답·실행 선택 불일치는 없었다. 새 모델 호출 0회이며 내부 판단 원인을 확정하거나 표현을 바꿔 해결했다고 주장하지 않는다.

## ‘여러 단계 양보만 실패했다’고 말해도 되나

그렇게 단정하면 정확하지 않다.

- [짧은 상태 48회 시험](kev-mapf-concise-probe-20261022.md)은 다중 양보 판단의 한계를 드러냈다. 두 대가 모두 비킨 상태에서 짧은 설명 KEV는 0/6이었다.
- 일반 주문의 최종 후보 선택도 항상 예상 최소를 따르지는 않았다. 위 비교에서는 3/22회 더 긴 예상 시간을 골랐다. 그 경로를 실행할 수 있다는 것과 목표에 맞는 최선의 후보라는 것은 별개다.
- KEV 경로 생성은 별도 시험에서 `순환 방지 조건을 만족하는 이동 후보가 없습니다`라는 실패를 기록했다. A* 경로와 KEV 교통조정으로 완료한 주문을 KEV 경로 생성 성공으로 세지 않는다. [기존 연결 기록](../order-traffic-integration.md).

반대로 이 오류들만으로 모든 일반 주문이 실패하거나 KEV가 어떤 역할도 할 수 없다고 단정할 수는 없다. 어느 기능·어느 입력·어느 목표를 검증했는지 구분한다.

## 이번 코드 기준 연속 주문 확인 결과

일반 주문의 선택만 `MIN_EXPECTED_TIME`으로 설정하고 경로는 A*, 가상 주행은 기존 0.2m/s를 사용한다. 임시 위치는 기존 대기 노드 N0·N1·N2로 맞추며, 원래 이력·모드·위치를 보관하고 종료 후 복원한다. 시험 주문 이력은 지우지 않는다.

seed 20261022의 주문 12건·물품 27개다. 처음 3건 이후 5초마다 한 건씩, 45초까지 등록한다. 대기열에 쌓인 주문은 가용 로봇이 생기면 기존 배차기가 처리한다. 별도 다중 양보를 일반 주문에 새로 연결한 시험은 아니다.

기존 실행·관측기를 재사용했고 실행 코드는 수정하지 않았다. 결과는 다음과 같다.

| 항목 | 관측 결과 |
| --- | --- |
| 완료 주문·물품 | 12건·27개 모두 완료 |
| 출고 모두 완료 | 약 131.24초 |
| 마지막 복귀까지 | 약 141.47초 |
| 등록 후 주문당 평균 완료 | 약 54.12초 |
| 실패·취소·복귀 오류 | 0건 |
| 노드·물리 엣지 중복 점유 | 748회 표본에서 0회 |
| 여러 후보 중 코드 선택 | 14회, 모두 제공된 예상 시간 최소와 일치 |
| 실제 KEV 선택 요청·오류 | 0회·0회 |
| 최대 대기 주문·진행 주문 | 7건·3건 |

약 15.63초에 1번 주문의 R1은 작업대로 이동 중이고, 2번 주문의 R2는 비워진 N5를 향해 이동 중이었다. 앞 주문 전체가 끝나기 전 다음 픽업 이동이 이어졌다. 표본에서 복귀 전 새 주문 배정도 1사례 관측했다. 배차 제한을 모두 충족하는지 재현한 검사는 아니지만 대기 주문이 있는데 가용해 보이는 IDLE 로봇이 쓰이지 않은 가장 긴 구간은 약 0.194초였다.

원래 시뮬·AI / A* 경로 / KEV 선택 설정과 원래 위치 N0·N11·N10으로 복원했다. 원래 이력 0건과 새 시험 12건을 보존해 종료 후 이력은 12건이다. 설정 변경은 시험 중에만 적용했고 운영 기본값을 코드 방식으로 영구 변경하지 않았다.

관측은 약 0.15초 대기 후 API를 조회한 표본이다. 모든 순간의 안전을 보장하거나 장시간 운용을 검증한 결과가 아니다. 이번 주문표는 이전 18건 비교와 다르므로 완료 시간을 직접 비교해 더 빨라졌다고 주장하지 않는다. 취소·고장·배터리 교체 같은 예외는 이번 정상 주문 시험에서 의도적으로 만들지 않았다.

실행 기록은 `logs/order-traffic-comparisons/20261022-code-stability12/`에 있다. `schedule.json`, `MIN_EXPECTED_TIME/report.json`·`samples.jsonl`, `analysis.json`, `verification.json`, `final-server-state.json`을 보관했다. 같은 폴더의 `driver.py`가 실행 도구이며 재시작 전 상태·시험 시작 위치·최종 복원 상태도 남겼다. 로그는 저장소 추적 대상이 아니므로 공유 시 별도로 포함한다.

**이 한 번의 코드 시험은 KEV와의 새 성능 비교나 실기체 검증이 아니다.**

## 후속 예외 시험: 예약 대기 중 취소

[예약 대기 취소·통로 해제·같은 로봇 재사용](reservation-wait-cancellation-20261022.md)을 별도로 확인했다. 재시험은 취소 1건·새 주문 완료 1건이며 길이 비어도 과거 주문은 재출발하지 않았다. 최초 관측 도구 오류로 대기 한도에 도달한 실패 주문도 보존하고 구분했다. 이 결과는 위 정상 주문 12건의 수치에 합치지 않는다.

## 후속 예외 시험: 출발 대기 한도와 재시도

[출발 전 60초 대기 한도·실패 이유·명시적 재시도](order-timeout-retry-20261022.md)를 새 주문 1건으로 확인했다. 실패 주문은 길이 비어도 자동 재출발하지 않고, 재시도 요청 후 R2가 완료했다. 687회 표본과 기존 자동 검사 3개가 확인 근거다. 원래 실패 이력을 보존했고 모델 호출은 없다. 홈 밖에서의 복귀 경로 차단과는 구분한다.

## 이후 진행 방향

후속 [홈 밖 복귀 차단·재사용](blocked-return-validation-20261022.md)까지 확인했다. R1은 N3에서 복귀를 180.09초 기다린 뒤 BLOCKED가 됐고 새 배차에서 제외됐다. 다른 R2는 별도 주문 두 건을 완료했다. 홈 밖 재시도 409, 운영자 통로 해제·실제 홈 복귀 후 명시적 재시도, R1의 별도 새 주문 처리까지 관측했다. 본 시험 1,748회·재사용 155회 표본에서 중복 점유 0회이며 모델 요청·관제 실행 코드 변경은 없다. 기존 16건과 새 4건을 보존하고 원래 설정·위치를 복원했다. 이는 KEV 성능 향상이 아니라 기존 예외 처리 동작의 근거다.

1. 일반 주문의 코드 기준을 안정성·평가 기준으로 유지한다. 이번 시험의 설정 변경은 임시다.
2. 여러 단계 양보의 KEV 확장은 중단하고 기존 구현·실험 기록을 보관한다.
3. 기존 완성 조정안 선택 방식은 별개로 남긴다. KEV를 쓴다는 이유만으로 검사를 없애거나 사용 범위를 확대하지 않는다.
4. 물류 성능을 주장하려면 새로운 상황·반복·같은 조건의 비교에서 완료율·주문 시간·처리량·대기·추론 비용을 함께 평가한다. 이번 안정성 확인을 성능 향상으로 발표하지 않는다.

교통조정 자체를 제거한 대조 시험은 이번에 하지 않았다. 따라서 전체 코드·예약·후보 생성의 기여와 KEV 선택의 기여를 혼동하지 않으며, ‘MAPF가 없는 경우보다 몇 % 개선’ 같은 숫자를 제시하지 않는다.

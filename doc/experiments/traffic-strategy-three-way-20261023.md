# 코드 탐색·KEV 전략 탐색·jhlee 전략 비교

후속 사용자 승인 비교: [같은 상태의 후보 확률 순서 재사용](traffic-strategy-probability-order-20261023.md). 기존 방식·결과를 보존한 별도 호출 절감 실험이다.

2026-10-23. 기존 관제와 분리한 첫 비교 계획과 구현. 실제 결과는 마지막 절에 구분해 기록한다.

## 무엇을 확인하나

**KEV에게 ‘이미 만든 계획 중 선택’ 대신 ‘어떤 해결 전략부터 시도할지’를 맡겼을 때, 같은 한도 안에서 더 좋은 계획을 찾는지 확인한다.**

| 방식 | 판단 흐름 |
| --- | --- |
| 코드 탐색 | 요청 순서의 로봇부터 기본 경로·공유 구간 회피 전략을 차례로 시험한다. 검사한 완성 계획 중 예상 평균 도착 시간이 작은 것을 보관한다. |
| KEV 전략 탐색 | KEV가 다음에 시험할 로봇과 기본 경로 유지·어느 공유 구간 회피를 선택한다. 그 뒤 코드가 필요한 A* 경로를 만들고 검사한다. 실패 이유와 현재까지 찾은 계획의 시간을 다음 질문에 포함한다. 최종 선택은 코드가 한다. |
| jhlee 전략 | 고정 커밋의 판단 엔진·지시문을 사용한다. 공유 구간 → 우선 로봇 → 대기·우회 → 대기 위치를 판단한다. 우회 생성만 공통 A*로 바꾸고, 제안을 공통 순차 실행 계획으로 바꾼 뒤 검사한다. |

코드와 KEV 탐색은 **같은 탐색 실행기에서 다음 전략의 선택 순서만 다르다.** jhlee 비교는 판단 구조·지시문·주어지는 계산 정보도 다른 **방식 전체 비교**다. 결과를 전부 AI 단독 효과로 해석하지 않는다.

이전 다중 양보 시험의 ‘다음 검사 동작 선택’과 방향은 이어진다. 이번 변경은 **경로를 만들기 전 대상·회피 구간을 선택**하며, 첫 유효 계획을 찾은 뒤에도 한도 안에서 다른 계획을 검토한다. 이전 실패 기록은 유지하고, 새 이름으로 성공을 가정하지 않는다. 기존 일반 주문 선택기는 이 실험의 비교 대상에 포함하지 않았다.

## 첫 비교에서 허용하는 동작

- 현재 노드에서 다른 로봇이 먼저 지나가기를 기다린다.
- 제공된 기본 경로로 이번 목적지까지 이동한다.
- 공유 노드·물리 엣지 또는 연결된 공유 구간을 피하는 A* 경로를 요청한다.

이동 단계는 로봇 하나가 목적지에 도착한 다음 다음 로봇이 출발하는 공통 규칙이다. 동시에 움직이는 최적 시간표를 찾는 시험은 아니다. 정차 로봇을 다른 곳으로 비켜줬다가 복귀시키기, 엣지 중간 정차, 실기체 아루코·작업 시작, 기존 활성 예약 변경은 포함하지 않는다.

`jhlee`의 WAIT도 이번에는 현재 노드 대기로 한정한다. 초기 정차 노드만 대기 허용 목록에 넣고, 다른 대기 위치로 이동해야 하는 제안은 실행하지 않는다. 우선순위는 한 번의 결정적인 순서 정렬로 변환하며, 잘못된 제안을 다른 코드 탐색으로 수리하지 않는다. 최종 예약 검사에서 탈락하면 출발하지 않는다.

| 판단 입력 | 코드/KEV는 탐색 실패 기록과 현재 최선 지표 사용. jhlee는 원본 입력·지시문을 보존하므로 ETA를 사용하지 않음 |

‘허용 동작이 같다’는 말이 ‘모든 방식이 반드시 같은 경로 후보를 만든다’는 뜻은 아니다. 어떤 공유 구간을 먼저 피하고 어떤 순서로 검토하는지가 비교 대상이다. 원본 jhlee의 순환 우선순위 제한·엄격한 엣지 회피 조건도 남긴다. 같은 엣지 회피 조건은 새 코드/KEV 탐색에도 적용한다.

## 탐색 한도와 결과 채택

최초 `equal_calls` 시험은 방식·상황당 예약 검사 최대 128회, 이동 단계 8개, 실제 판단 시간 10초, 우회 생성 호출 16회, KEV 호출 8회, 개별 모델 요청 2초다. 코드도 같은 검사·경로 생성·시간 한도를 사용한다. 선택지가 하나면 모델 호출을 생략한다. jhlee 원본의 반복 상한은 16회이며 별도로 기록한다.

### 사용자 승인 후속: 같은 시간 안에서 비교

사용자는 AI 도입의 유용성을 검토하는 것이 목표이며 성능 개선을 전제로 하지 않는다고 확인했다. 8회 호출 한도 때문에 계획 완성 전에 끝난 결과를 원본 방식의 한계로 해석하지 않도록, **`equal_time` 비교를 같은 5상황에 각각 1회 추가**한다. 지시문·모델·상황은 바꾸지 않고 총 모델 호출 상한만 `null`로 제거한다. 공통 판단 시간 10초·검사 128회·우회 호출 16회·단계 8개·개별 요청 2초는 유지한다. 호출 수는 결과로 기록한다. 이전 8회 비교 기록도 그대로 보존한다.

jhlee는 ‘항상 3번 호출’하는 엔진이 아니다. 구간 선택·우선순위·행동·대기 위치를 분리해 물을 수 있고 선택지가 하나면 생략하며 여러 충돌을 반복 처리한다. **원본의 3은 기본 우회 시도 상한**이고, 반복은 엔진 기본 16회·실제 시뮬 게이트 설정 20회다. 이번 어댑터는 계속 엔진 16회와 공통 우회 16회를 사용한다. 이 후속은 호출 상한만 바꾼 비용 조건 비교이며 **원본 우회 3회·게이트·AI 경로 생성을 그대로 복원한 원형 시험은 아니다.**

세 방식은 한 컴퓨터에서 순서대로 실행하지만 각 실행마다 새 입력 사본·예약표·가상 로봇 저장소를 만든다. 두 모델 방식은 하나의 모델 서버를 공유한다. 기존 FastAPI 관제 프로세스·주문 목록·실제 로봇 상태는 사용하지 않는다. 앞으로 한 관제에 붙인다면 하나의 요청당 한 판단기를 고르고 기존 예약·실행 경계로 보내야 한다. 세 판단기가 같은 로봇에 각각 명령하도록 연결하지 않는다.

시간·호출 한도나 모델 오류로 끝나도 **이미 한도 안에서 전체 검사를 통과한 완성 계획**은 사용할 수 있다. 그런 계획이 없으면 정지한다. 미완성 계획은 실행하지 않는다. 마지막 허용 검사에서 찾은 유효 계획은 사용할 수 있으나, 시간 한도 뒤 끝난 검사·모델 응답은 채택하지 않는다.

동기 검사 하나와 진행 중 HTTP 요청을 강제로 중단하는 기능은 아니다. 검사 사이의 한도 확인과 늦은 응답 폐기로 구현한다. 첫 유효 계획 발견 시점·최종 종료 이유·모델 질문과 응답·실패 피드백·우회 요청·검사 기록을 남긴다.

## 실제 모델 비교 전에 고정하는 판단 기준

1. 첫 단계는 5상황×3방식, 각각 1회만 실행한다. 최대 모델 호출은 두 모델 방식×5상황×8회=80회이며 실제로는 단일 선택에서 생략된다. 필요한 경우 공통 준비용 모델 호출은 1회만 별도로 기록한다.
2. 정상 4상황 완료 여부와 출발 금지 1상황에서 부분 계획을 실행하지 않는지 먼저 본다. 모델의 잘못된 응답·한도·검사 실패도 모두 보고한다.
3. 해결률과 함께 예상 평균 도착 시간, 실제 가상 실행 평균, 첫 계획까지의 판단 시간, 총 판단 시간, 검사·우회·모델 호출 수를 비교한다. 가상 실행 시간에 실제 판단 시간을 더한 값은 별도 합성 지표이며 실측 주문 처리 시간이 아니다.
4. 코드 대비 해결률이 낮아지거나, 해결된 상황에서 더 좋은 계획·더 적은 검사 같은 이점이 전혀 보이지 않으면 입력 튜닝·반복 호출을 이어가지 않고 원인과 한계를 보고한다. 이때 실제 모델 응답 분석은 추가 호출 없이 한다.
5. 이점이 일부 보이더라도 1회 시험으로 우수성을 선언하지 않는다. 다음 반복·다른 상황 시험의 필요성을 별도로 검토한다. 일반 주문·화면 연결은 이 단계 결과를 보고 결정한다.

## 실행 결과

**최초 8회 상한 조건에서 실제 모델로 5상황×3방식=15회 비교를 완료했다. 이 조건에서는 KEV가 코드보다 유리하다는 근거를 얻지 못했다.** 이 결과 뒤 사용자가 승인한 총 호출 상한 없는 시간 기준 후속과 구분한다. 지시문 수정·모델 튜닝은 진행하지 않는다.

기존 8011 서버는 꺼져 있었다. 제한 환경의 GPU 조회는 실패했지만 제한 밖에서는 RTX 4070 SUPER가 정상 확인됐다. 캐시된 `jaredpalmer/kev-0.8b@v1.0`을 CUDA / torch / bfloat16, temperature 2.3510958125672174, prefix cache 꺼짐으로 임시 **8012** 포트에서 실행했다. 시험 뒤 이 임시 서버만 정상 종료했다. 기존 FMS를 시작·중단하거나 일반 주문을 넣지 않았다.

### 차이가 난 부분을 쉽게 해석하면

세 대 출발에서 코드는 R1 진행 → R2의 비교적 짧은 우회 → R3 진행을 찾았다. KEV 탐색은 **R2를 긴 우회로 먼저 보내는 계획**을 찾고, 다른 가지를 탐색하다 모델 호출 8회 한도에 도달했다. 이미 전체 검사를 통과한 계획이 있어 그 계획만 가상 실행했다. 부분 계획을 실행한 것이 아니다.

- 코드: 검사 36회, 우회 요청 16회, 판단 약 **0.021초**, 첫 완성 계획까지 약 0.002초.
- KEV 탐색: 검사 11회, 우회 요청 7회, 모델 8회, 판단 약 **1.645초**, 첫 완성 계획까지 약 0.482초.
- 실제 가상 이동 평균: 코드 **19.900초**, KEV 탐색 **24.067초**. 예약·이동기 시간 단위·단계 간 대기가 포함돼 예상 평균과 조금 다르다.

검사 수만 줄었다고 효율이 좋아졌다고 보지 않는다. 이번에는 계획 품질이 나빠졌고 실제 판단 시간도 늘었다. 같은 품질의 계획을 더 적은 비용으로 찾은 결과가 아니다. 코드도 우회 요청 16회 한도에서 끝났으므로 전역 최적해라고 주장하지 않는다.

jhlee는 세 대 출발에서 공유 구간·우선 로봇·대기를 여러 번 판단하다 **완성 제안을 내기 전에 공통 모델 8회 한도**에 도달했다. 이것은 이번 비용 한도의 결과이며, 한도를 늘려도 풀 수 없다는 증거가 아니다. 대기 선택과 우회 선택의 지시문도 원본 그대로여서 전체 알고리즘 차이가 포함된다.

정차 로봇 우회 상황에서는 R2가 N7에서 계속 정차하는데 jhlee가 R1의 WAIT를 선택했다. R2에게 떠날 요청이 없어 길이 열리지 않으므로 공통 예약 검사에서 탈락했다. 검사 없이는 ‘기다리면 풀린다’고 잘못 해석할 수 있는 상황이다. 원본 실제 관제의 장기 재판단·주문 흐름 전체를 실행한 것은 아니다.

### 호출 수·검증과 기록

모델 비교 호출은 새 KEV 탐색 **13회**, jhlee **11회**, 합계 **24회**다. 공통 준비 호출 1회는 별도다. 모델 호출을 생략한 단일 선택 상황도 포함하므로 ‘15회 모두 KEV가 판단했다’는 뜻은 아니다.

실행한 완성 계획 10개를 새 호출 없이 다시 검사했고, 가상 이동 **2,905회 점유 표본에서 중복 점유가 없었다.** 15회 입력 해시·한도 일치, 모델 호출 수, 미해결 시 실행 없음, 원본 소스 해시도 검사했다. 모든 물리 안전 조건이나 임의 대수에 대한 보증은 아니다.

새 자동 검사 **15개**, 전체 자동 검사 **296개**가 통과했다. 모델 성능 성공 횟수와 별개로 입력 보존·같은 탐색 조건·실패 피드백·호출 한도·늦은 검사 결과 거부·유효 완성 계획만 실행을 확인한다. 전체 검사에는 기존 경고 4개가 있다. 제한 환경에서 기존 비동기 검사가 멈춰 시간 한도로 종료됐고, 제한 밖에서 재실행해 통과했다.

초기 준비 도구는 A* 반환 키 `node_ids`를 입력의 `path`로 변환하지 않아 중단됐다. 실제 모델 비교 전에 수정·재검사했고 이 초기 기록도 지우지 않았다. 실제 시험 후에는 잘못된 모델 응답의 choice가 문자열이 아닌 경우를 거부하는 검사를 보완했다. 이번 실제 응답은 모두 문자열이라 이 보완으로 결과는 달라지지 않는다. 시험 당시 소스 사본과 해시는 그대로 보존했다.

**최초 호출 상한 시험의 결론:** 전략을 먼저 제안하는 연결 자체는 작동한다. 그러나 로봇 3대·이 공통 동작·한도·현 모델에서는 더 좋은 해결 성능을 확인하지 못했다. 기존 일반 주문이나 화면의 기본 판단기를 이 방식으로 바꾸지 않는다. 이후 사용자 승인으로 아래 시간 기준 비교를 한 번 추가했으며, 모델 튜닝·실기체 적용을 자동으로 이어가지 않는다.

jhlee는 **9번째 호출까지 진행해 제안을 완성**했다. R1→R2→R3의 우선순위와 대기를 제안했는데, R1이 N5에 도착해 남아 있으면 R2의 기본 경로가 N5를 지나 N6로 갈 수 없다. 완성 제안을 공통 순차 실행으로 옮긴 뒤 예약 검사에서 탈락했다. 이번에는 호출 한도 때문에 미완성된 것이 아니다. 실제 일반 주문에서 R1의 다음 작업·출발로 N5가 비워지는 장기 흐름을 시험한 것은 아니므로, 전체 관제에서도 무조건 막힌다는 뜻은 아니다.

새 KEV 탐색은 R2를 N1→N9→N7→N11→N6로 먼저 보낸 뒤 R1·R3를 보내는 계획을 찾았다. 최초 8회 시험의 긴 우회보다 좋아졌으나, 이번 코드 계획보다 예상 평균이 약 0.816초 길었다. 실제 가상 이동 평균은 코드 19.900초·KEV 20.717초다. 각 조건을 한 번씩만 실행했으므로 호출 상한 해제의 일반적인 효과 크기로 추정하지 않는다.

공통 준비 1회를 제외한 모델 호출은 총 **42회**다. 실행한 완성 계획은 다시 예약 검사했고 점유 표본 **2,838회에 중복이 없었다.** 새 자동 검사 18개가 통과했다. 전체 검사는 모델 시작과 겹친 첫 실행에서 기존 0.03초 시간 제한 검사가 명령 전 시간 초과로 실패해 298개 통과·1개 실패였고, 모델 종료 후 단독 재실행에서는 **299개 통과·기존 경고 4개**였다. 해당 기존 검사나 관제 코드를 수정해 결과를 맞추지 않았다.

두 비용 조건은 별도 결과로 보존한다. ‘호출 8회 안에서 완료하는가’와 ‘같은 시간 안에서 어떤 계획을 찾는가’는 다른 질문이다. 원본 전체 시스템 비교가 필요하다면 jhlee의 우회 3회·실제 게이트·AI 경로 생성 등도 별도로 평가해야 한다.

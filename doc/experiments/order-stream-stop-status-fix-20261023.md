# 주문 공급 중지 후 완료·복귀 표시 갱신

2026-10-23. 우리 KEV 전략 순서 방식의 연속 주문 점검에서 발견한 표시 문제를 수정했다. 교통조정의 판단 방식이나 배차 규칙을 바꾸는 작업은 아니다.

## 어떤 문제였나

[직전 연속 주문 시험](our-strategy-continuous-validation-20261023.md)에서 주문 12건은 실제 작업·홈 복귀까지 완료했다. 하지만 자동 공급을 멈춘 순간에는 7건만 완료돼 있었고, 시나리오 통계는 그 값에 머물렀다. 공급 루프가 끝나면서 통계 갱신도 끝났기 때문이다.

**주문 공급 중지**는 새 주문 등록만 멈춘다. 이미 접수한 주문은 계속 처리하므로, 화면의 완료·복귀 건수도 계속 갱신돼야 한다.

## 바뀐 흐름

```text
주문 공급 중지 → 신규 등록 중단
                    ↓
              접수 주문은 계속 처리
                    ↓
화면의 상태 조회 → 이번 공급기가 등록한 주문의 최신 상태 집계
                    ↓
              작업 완료·복귀 중·실패·취소 건수 표시
```

[scenario_service.py](../../backend/app/services/scenario_service.py)의 상태 조회는 저장된 시나리오 상태를 복사한 뒤, 해당 공급기가 등록한 주문 ID에 대해서만 최신 주문 상태를 집계한다. 중지 후 표시 문구에도 건수를 덧붙인다. 실패로 중지된 경우에는 원래 실패 상태와 이유를 유지한다.

집계는 [order_stream_scenario.py](../../backend/simulation/order_stream_scenario.py)의 공통 함수를 재사용한다. 조회가 주문을 추가하거나 수정하지 않고, 내부의 공급 종료 기록도 바꾸지 않는다. 다른 사람이 따로 넣은 주문은 이번 공급 통계에 섞지 않는다.

`작업 완료`는 주문 작업이 끝난 건수다. 그중 아직 홈으로 돌아가는 주문은 `복귀 중`에도 포함될 수 있다. `작업 완료 12 · 복귀 중 0`과 로봇의 홈·대기 상태를 함께 확인해야 작업·복귀가 모두 끝났다고 볼 수 있다. 시나리오의 `completed`는 공급 실행 종료이며 모든 주문의 복귀 완료를 뜻하지 않는다. `elapsed` 역시 공급 실행 시간으로 유지한다.

## 확인한 내용

- 관련 자동 검사 **272개 통과**. 공급 중지 뒤 완료·복귀 변화 반영, 추가 공급 없음, 별도 주문 제외, 실패 이유 유지, 반복 조회 시 문구 중복 방지를 확인했다. 기존 경고 4개는 남아 있다. 전체 프로젝트 검사 통과를 뜻하지 않는다.
- 저장된 실제 12건 시험 결과를 별도 프로세스의 상태 API에 넣어 확인했다. 수정 전 통계의 완료 7건이 조회 시 **완료 12건·복귀 중 0건**으로 바뀌었고, 주문 원본과 내부 공급 기록은 유지됐다. 이는 저장 결과를 재사용한 API 확인이며 새로 12건을 운행하거나 모델을 호출한 시험은 아니다.
- 화면용 시뮬 백엔드는 모든 로봇이 홈에서 대기하고 진행 주문이 없는 것을 확인한 뒤 재시작했다. 기존 완료 주문 **6건**, 정확한 로봇 위치·이동 식별자, 시나리오 상태, 교통조정 설정의 보존을 전후 대조했다. 프런트와 KEV 서버는 유지했고 실제 로봇은 움직이지 않았다.

확인 기록은 `logs/order-stream-status-fix/20261023/`의 `api-replay.json`, `visible-before.json`, `live-restart.json`에 있다. 앞선 12건 운행 원문은 원래 로그에 보존했다.

## 직접 확인하기

1. 현재 관제 화면을 새로고침한다. 시뮬·AI와 `새 방식 · KEV가 전략 순서 제안` 설정을 확인한다.
2. 시나리오에서 **일반 주문 · 계속 주문 넣기**를 실행한다.
3. 원하는 시점에 **주문 공급 중지**를 누른다. 신규 주문은 늘어나지 않고 이미 접수한 주문은 계속 움직여야 한다.
4. 아래 상태 줄의 **작업 완료**가 늘고 **복귀 중**이 마지막에 0이 되는지 본다. 실패 건수와 로봇 홈·대기 상태도 함께 확인한다.

이번 수정은 표시 갱신 문제의 해결이다. 장시간 무고장이나 KEV의 성능 우수성을 새로 검증한 결과는 아니다.

## 되돌릴 때

변경 전 파일은 `logs/change-snapshots/20261023-before-stream-status-fix/`에 보관했다. 복원 도구는 이후 파일 변경이 있으면 덮어쓰지 않으며, 기본 실행은 복원 예정 목록만 보여준다. 이 복원은 이번 코드·문서 변경에 한정된다. 이미 실행 중인 서버에 반영하려면 주문·위치 보존 여부를 다시 확인하고 별도로 재시작해야 한다.

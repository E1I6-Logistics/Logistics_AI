# 무작위 주문 20건 연속 처리 결과

2026-10-20 · 실행 `7c889e929c3b40c79e944315d08d2475` · 시뮬·AI · A* 경로 생성 + KEV 교통조정.

**20건·57개 물품의 작업을 모두 마쳤고, 최종 로봇 3대도 대기 위치로 돌아왔다. 실패·취소·관측된 중복 점유는 없었다.**
KEV가 제공 후보의 예상 최소 시간을 따르지 않은 선택 1건과 배차·픽업대 대기를 확인했다.

## 현재 구현과 시험 범위

일반 주문 등록 → 기존 배차 → A* 경로 → 기존 경로·동적 우회 예약 검사 → 복수 후보면 KEV 선택 → 최신 상태 재검사 → 기존 주행기.
다른 로봇의 진행·예약은 유지하며 새로 출발하는 요청만 조정한다. 주행 중 로봇들의 계획을 공동으로 교체하는 기능은 아직 없다.
같은 픽업대의 앞 로봇이 떠나면 뒤 로봇이 접근하는 수정이 적용된 상태다.

- 기존 화면의 `continuous_ai_orders`를 그대로 사용했다. seed=42, 처음 3건, 이후 5초 간격, PENDING 상한 3건.
- A/B/C/D 합계 1~5개. 20건에 도달한 약 132.1초에 공급을 멈추고 남은 작업을 끝까지 관측했다.
- 기존 주문 이력과 다른 주문은 취소하거나 초기화하지 않았다.
- 현재 관제의 기본 시뮬레이션 속도 0.2m/s를 사용했다. 별도 가상 로봇의 5m/s 시험 결과와 구분한다.

## 발견한 선택 문제

`STREAM-7c889e-008`의 R3 복귀에서 KEV가 아래 두 후보 중 기존 경로를 골랐다.

| 방법 | 거리 | 예약 대기 예상 | 요청 완료 예상 |
| --- | --- | --- | --- |
| 기존 경로 3→11→7→9→2 | 2.046m | 4.532초 | 14.763초 |
| 우회 3→11→12→8→7→9→2 | 2.664m | 거의 0초 | 13.318초 |

거리만 보면 기존 경로가 짧지만, 대기까지 더하면 우회가 약 1.44초 빠른 예상이다.
현재 목표는 예약 대기를 포함한 완료 예상 최소이므로 이 선택은 기준과 맞지 않는다.
모델이 거리·기존 경로 표현에 영향을 받았을 가능성은 있지만 내부 원인은 이 한 번으로 확정할 수 없다.

이 주문은 76.69초에 RETURNING, 77.22초에 COMPLETED로 바뀌었고 로봇은 다음 주문으로 전환됐다.
따라서 **시스템이 실제로 1.44초 늦어졌다고 주장하지 않는다.** 같은 조건의 다른 후보를 실행한 대조 시험도 없다.
선택 기준을 확인하는 회귀 사례로 보관하고, 후보 표시 순서·이름·대기 표현을 바꿔 재검사하는 것이 다음 작업이다.

후속 분석을 마쳤다: [선택 원인 진단 결과](order-traffic-selection-diagnosis-20261020.md).
재구성한 상태에서는 같은 오류가 반복됐지만, 지시문을 짧게 바꿔도 다른 사례에서 오류가 남아 운영 표현은 교체하지 않았다.
정확한 원문 재전송을 위한 입력·응답 기록 코드도 보완했다. 과거 요청 전체가 미보관이어서 이번 재구성 시험의 한계를 구분했다.

## 처리량 관점에서 추가로 볼 부분

배차 대기 최대 34.9초, 픽업 차례 대기 최대 18.0초가 관측됐다.
픽업 차례 대기는 같은 픽업대를 한 대씩 쓰는 데 따른 대기이며, 앞 주문의 복귀까지 기다리던 버그와 구분한다.

예를 들어 약 55.4초에는 픽업 차례를 기다리는 로봇이 있는 동안, N6부터 방문하는 11번 주문이 PENDING이었다.
그때 N6의 현재 점유·직접 목표는 관측되지 않았다. 다만 전체 예약을 바꿔 실제 실행 가능성을 비교한 것은 아니므로 N6 주문을 먼저 보냈으면 반드시 빨랐다고 단정할 수 없다.
**배차할 때 픽업대 상황도 고려할 여지가 있다는 관측**이다. 배차 정책 변경은 해당 담당과 합의한 뒤 별도 비교해야 한다.

## 판단과 다음 시험

1. 이번 설정과 물량에서는 연속 처리가 끊기거나 실패하는 증상을 재현하지 못했다.
2. KEV의 시간 기준 위반 1건은 재현 입력을 고정해 원인을 더 분리한다. 임의로 코드 최솟값으로 바꿔 KEV 성공으로 기록하지 않는다.
3. 배차·픽업 대기는 오류로 단정하지 않고 주문 순서·픽업대 상황을 반영한 대조 정책과 비교한다.
4. seed를 바꾸거나 공급 간격·건수를 늘리는 시험은 그다음이다. 20건 성공이 장시간 운용·실기체 안전·규모 확장을 보장하지 않는다.
5. 다른 선택 방식과 같은 주문·초기 상태로 비교하지 않았으므로 KEV가 처리량을 높였다는 결론은 내리지 않는다.

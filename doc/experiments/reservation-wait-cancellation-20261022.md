# 출발 대기 중 취소한 주문이 길이 비어도 다시 출발하지 않는지 확인

2026-10-22. 기존 관제의 가상 로봇으로 **예약 가능한 경로를 기다리는 중 취소 → 통로 해제 → 같은 로봇에 새 주문**을 확인했다. 재시험은 취소 1건·새 주문 완료 1건이며 기존 실행 코드는 수정하지 않았다. KEV 호출 없이 A* 경로·코드 선택을 사용했다.

## 이미 검증한 것과 이번 차이

[이전 취소 시험](order-cancellation-followup-20261021.md)에서 미배차·픽업 차례 대기·픽업 작업·픽업 이동·작업대 이동·작업대 작업 중 취소와 로봇 재사용을 확인했다. 이번에는 픽업 차례 대기와 구분해 **교통조정에서 예약할 경로가 없어 출발하지 못하는 상태**를 만들었다.

```text
R1=N0: N5로 가는 주문을 받음
R3=N10: R1이 나가는 길을 막고 정차
  ↓
R1은 WAITING_FOR_SAFE_ROUTE, 이동 명령 없음
  ↓
그 주문만 취소 → R1은 이미 홈 N0이므로 복귀 완료
  ↓
R3를 기존 수동 이동 API로 N2에 보냄
  ↓
길이 비어도 취소된 R1 주문이 다시 출발하지 않는지 관측
  ↓
R1에 새 A 1개 주문 → 픽업·작업대·복귀까지 완료
```

N0에서 N5로 계산된 기본 경로는 N0→N10→N8→N7→N5였다. N10을 제외하면 연결 경로가 없다. 기본 경로의 예약 불가와 우회 생성 실패를 별도 복사 상태에서 먼저 확인한 뒤 관제 시험을 시작했다. 이는 운영에서 자연 발생한 막힘이 아니라 의도적으로 만든 정지 배치다. R3 양보를 KEV가 결정한 것이 아니라 시험 도구가 수동 이동 API로 통로를 해제했다.

## 정상 관측한 재시험 결과

시각은 재시험 도구 시작 기준이며 시험 준비·백엔드 재시작도 포함한다.

| 시각 | 확인한 내용 |
| --- | --- |
| 약 2.26초 | R1의 교통조정이 `WAITING_FOR_SAFE_ROUTE`. R1은 N0, 경로·이동 목표 없음 |
| 약 2.26초 | 이번 실행에서 등록한 주문 하나만 취소 |
| 약 2.42초 | 취소 주문 `CANCELLED`, 복귀 상태 `RETURNED` |
| 약 2.42초 | 길을 막던 R3를 N2로 이동시킴 |
| 약 8.72초 | R3 이동 중·도착 뒤에도 R1이 N0에 머무름. 취소 주문 재출발 없음 |
| 약 8.88초 | 새 주문이 같은 R1에 배차됨 |
| 약 37.87초 | 새 주문의 작업·복귀 완료. 취소 주문은 계속 취소 상태 |

- 원본 상태 관측 **317회**, 노드·물리 엣지 중복 점유 관측 0회.
- 취소한 주문은 계속 `CANCELLED`, 복귀 상태는 `RETURNED`.
- 새 주문은 같은 R1이 받아 `COMPLETED`까지 처리했다.
- 종료 시 로봇 모두 IDLE·경로 없음·목표 없음. 픽업 대기열·예약 로봇 목록이 비었고 작업대도 모두 FREE였다.
- 실제 모델 선택 요청 0회. 취소 후 복귀는 기존 알고리즘 기능이다.
- 실행 코드 해시는 시험 전후 동일하다.

통로 해제 후 새 주문을 넣기 전까지의 표본에서 R1의 위치·경로·목표를 다시 검사했다. 새 주문을 넣은 뒤의 정상 출발을 과거 취소 주문 재출발과 혼동하지 않았다. 약 0.075초 대기와 API 호출 시간이 합쳐진 표본 관측이며 모든 순간의 안전이나 실기체 안전을 증명한 것은 아니다.

## 최초 관측기 오류와 시간 한도 처리를 숨기지 않는다

최초 실행 도구에는 기록 함수 인자 `name`과 주문 이름 `name`이 충돌하는 오류가 있었다. 첫 주문은 관제에 정상 등록됐지만 도구의 관측이 직후 중단됐다. 이후 관제의 기존 60초 교통조정 대기 한도에 따라 그 주문은 `FAILED`가 됐고 로봇은 `RETURNED`까지 자동 복귀했다.

이 최초 실행을 ‘예약 대기 중 취소 성공’으로 세지 않았다. 해당 주문을 취소했다는 기록도 만들지 않았다. 실패 원인은 대기 한도이며, 도구가 계획한 취소 시점을 놓친 경위를 함께 보관했다. 관측 도구의 인자 이름만 수정하고 기존 이력·설정·위치를 복원한 뒤 새 시험 주문으로 재시험했다. 관제 코드는 바꾸지 않았다.

- 최초 실행 기록: `logs/order-cancellation-runs/20261022-reservation-wait/`.
- `report.json`은 관측 중단을 실패로 남긴다.
- `settled-after-observer-error.json`에 해당 주문의 최종 `FAILED`·`RETURNED`를 보관했다.
- `restored-after-observer-error.json`에 원래 설정·위치 복원을 보관했다.

따라서 이번 전체 작업에서 추가한 주문은 **3건: 최초 시도 실패 1건, 재시험의 의도한 취소 1건, 새 주문 완료 1건**이다. 모든 이력을 보존했다. 최초 실패를 일반 주문 처리 오류로 감추거나, 재시험 결과만 합쳐 ‘전체 실패 0건’이라고 표현하지 않는다.

## 코드 검사와 원래 상태 보존

교통조정 관련 기존 자동 검사 24개 통과. MQTT의 기존 API 사용 경고 1개가 남아 있다. 이 검사는 모델 성능 평가와 별개다. 제한된 실행 환경에서 멈춘 최초 검사 프로세스는 종료했고, 실행 제한 밖에서 60초 한도로 재실행해 통과를 확인했다.

정상 재시험 원본 관측을 별도로 다시 읽어 다음을 확인했다: 예약 대기 실재, 취소 유지, 통로 해제 후 재출발 없음, 같은 로봇 재배차·완료, 중복 점유 없음, 기존 이력 보존. 종료 후 원래 시뮬·AI / A* 경로 / KEV 선택과 N0·N11·N10 위치·자세·배터리를 복원했다.

작업 전 이력 12건은 내용까지 보존했다. 최초 시도 1건과 재시험 2건을 더해 최종 이력은 **15건: 완료 13건·취소 1건·실패 1건**이다. 새로운 KEV 실험·모델 변경·실기체 이동은 하지 않았다.

## 재현 근거

정상 재시험 기록은 `logs/order-cancellation-runs/20261022-reservation-wait-verified/`에 있다.

- `driver.py`: 기본 실행은 배치·경로 확인만 한다. `--run`은 기존 관제에 시험 주문을 등록하고 빈 백엔드를 재시작한다.
- `waiting-before-cancel.json`, `cancel-response.json`: 취소 전후 상태.
- `unblocked-without-relaunch.json`: 통로 해제 후 과거 주문이 다시 시작하지 않은 상태.
- `samples.jsonl`: 317회 원본 관측.
- `settled-before-restore.json`, `final-server-state.json`: 완료·자원 해제와 원래 설정·위치 복원.
- `source-sha256.json`, `report.json`, `verified.json`: 실행 코드 불변·결과와 원본 재검증.

로그 폴더는 저장소에서 추적하지 않으므로 공유 시 별도로 포함한다. 이번 문서 수정 전 백업은 `logs/change-snapshots/20261022-before-reservation-cancel-docs/`에 보관했다.

연결 끊김·복귀 경로 장기 막힘·실물 적재 물품 정산·모델 응답 지연 중 취소는 이번 시험에 포함하지 않았다. 별도 다중 양보를 일반 주문에 자동 연결한 시험도 아니다.

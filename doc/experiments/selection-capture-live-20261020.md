# 일반 주문의 실제 KEV 입력·응답 기록 확인

2026-10-20 10:18~10:20(KST). 이번 목적은 **기존 관제의 실제 KEV 요청·응답이 원문 그대로 저장되는지 확인하는 것**이다. 일반 계산 방식과의 성능 비교 시험은 아니다.

## 반영한 것

- 기존 관제에서 진행 중 주문·복귀·시나리오가 없고, 3대 모두 대기 상태인지 확인했다.
- 백엔드만 재시작했다. 기존 주문 이력 42건, 로봇 위치, 시뮬·AI 모드를 복원했다. 프런트·KEV 서버는 재시작하지 않았다.
- 지시문·후보 생성·선택 방식·예약 검사·이동 속도는 바꾸지 않았다.
- `selection-inferences.jsonl`의 요청 ID로 REQUEST와 RESPONSE 또는 ERROR를 연결한다. RESPONSE는 모델 응답 기록이며 실제 이동 승인은 아니다.
- 관련 자동 검사 21개 통과. 기존 MQTT 사용 중단 예정 경고 1개가 있었다. 전체 자동 검사를 다시 실행한 숫자는 아니다.

재시작 전 상태와 복원 결과: 백업 폴더 (`logs/restart-backups/20261020-101800-selection-logging`, 로컬 보관).

## 기존 관제에서 실행한 시험


- 시뮬·AI, A* 경로 생성 + KEV 교통조정, 기존 속도 0.2m/s.

- 이전 20건 시험과 같은 seed다. 새로운 주문 분포에 대한 일반화 검증으로 해석하지 않는다.

## 저장된 입력을 직접 보는 방법

- 실제 KEV 입력 예시 (`logs/random-order-runs/20261020-101820/example-kev-request.json`, 로컬 보관): 후보 3개가 있었던 호출. `state`에 로봇 상태와 남은 경로, `questions.order_traffic`에 지시문과 후보가 있다. 후보의 값은 JSON 문자열이다.
- 같은 호출의 서버 응답 (`logs/random-order-runs/20261020-101820/example-kev-response.json`, 로컬 보관): `answers.order_traffic.choice`가 선택 결과다.
- 요청·응답 전체 기록 (`logs/order-traffic/selection-inferences.jsonl`, 로컬 보관): 이후 호출도 계속 추가된다. 이번 시험은 아래 검증 파일의 주문 ID·요청 ID로 구분한다.
- 원문 보존 검사 결과 (`logs/random-order-runs/20261020-101820/selection-capture-verification.json`, 로컬 보관).
- 주문·로봇 관측 결과 (`logs/random-order-runs/20261020-101820/report.json`, 로컬 보관).

예시 호출에서는 R3가 N5로 가는 세 경로 중 기존 경로를 골랐다. 제공된 예상 완료 시간은 기존 경로 약 7.51초, 우회 1 약 22.42초, 우회 2 약 15.86초였다. 이 숫자는 후보의 계산상 예상이며 실제 도착 시간 측정값은 아니다.

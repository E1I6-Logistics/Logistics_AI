# 거리·시간 정보를 추가한 뒤에도 KEV가 놓친 선택

2026-10-22. [거리·시간 입력 비교](kev-mapf-recovery-motion-input-20261022.md)의 저장된 답변 108개를 사후 분석했다. **새 모델 호출 0회, 관제 명령 0회**다. 실행 코드·설정·로봇 위치를 바꾸지 않았다.

## 어떻게 확인했나

실행 당시 저장한 지도·경로·허용 양보·최대 8단계를 사용한다. 원본 입력 해시와 가상 위치를 확인하고, 각 선택 뒤 제공된 이동을 조합해 원래 목적지 도착·양보 로봇 복귀까지 가능한지 기존 예약 검사로 확인했다.

이 사후 계산은 운영 시 모델에게 답을 알려준 과정이 아니다. 온라인 검사 횟수·모델 호출·시간 한도를 적용한 성능 경쟁도 아니다. 사후 정답 계산에 사용한 예약 검사 320회는 앞선 실행 성능 수치에 더하지 않는다.

판정은 제공된 경로와 ‘로봇당 양보 1회’라는 이번 시험의 제한 안에서만 유효하다. 다른 경로·재양보·지도 전체의 해결 가능성을 판정한 것이 아니다. 이미 방문한 탐색 상태의 제외와도 구분한다.

## 두 대 양보: KEV 단독의 세 번 모두 같은 선택 흐름

처음 R1은 N3→N0으로 가야 한다. R2=N11, R3=N10이 길을 막는다. R2는 N6, R3는 N8로 비킨 뒤 R1이 통과하면 원위치로 돌아올 수 있다.

아래는 거리·시간 정보를 받은 KEV 단독 3회에서 동일하게 기록된 흐름이다. **계획을 검토하는 복사 상태**이며 잘못된 제안대로 실제 로봇을 움직인 것은 아니다.

| 호출 | KEV가 고른 것 | 사후 확인 | 당시 해결로 이어지는 선택 |
| --- | --- | --- | --- |
| 1 | R1부터 출발 | R2·R3가 막고 있어 지금 이동 불가 | R2 또는 R3 양보 |
| 2 | R3가 N8로 비키기 | 이후 끝까지 해결 가능 | R2 양보도 가능 |
| 3 | R3가 비킨 순서를 미루기 | 해결 가능한 다음 이동이 남아 있음 | R2 양보 |
| 4 | R2가 비킨 다른 순서도 미루기 | 해결 가능한 다음 이동이 남아 있음 | R3 양보 |
| 5 | R3를 N10으로 먼저 복귀 | 이 이동은 가능하지만 이후 R1 통과 불가 | R2 양보 |
| 6 | 조기 복귀한 순서를 미루기 | 이 순서의 남은 이동으로는 해결 불가 | 제시된 다음 이동 중 없음 |
| 7 | R3만 비킨 상태에서 R1 출발 | R2가 N11을 막고 있어 지금 이동 불가 | R2 양보 |
| 8 | 두 대 모두 비킨 순서를 미루기 | R1을 보내면 끝까지 해결 가능한 상태 | R1 출발 |

이후 모델 호출 8회 한도에 도달해 미해결 종료했다. **사람이 보는 로봇의 대기 명령과 ‘이 순서를 미루기’는 다르다.** 후자는 계획 탐색 안의 선택이며, 실제 로봇 이동은 완성 계획이 없어서 시작하지 않았다.

## 횟수는 무엇을 세었나

거리·시간 정보가 있는 KEV 단독: **3회 실행 × 호출 8회 = 선택 24개**다. 서로 다른 상황 24개를 만든 것은 아니다.

| 선택 분류 | 개수 |
| --- | ---: |
| 지금 이동 불가 | 6 |
| 이동 자체는 가능하지만 이후 완성 불가 | 3 |
| 완성 계획으로 이어질 수 있는 이동 | 3 |
| 완성으로 이어지는 다음 이동이 있는데 현재 순서를 미룸 | 9 |
| 제시된 다음 이동에 완성 가능 선택이 없는 순서에서 미룸 | 3 |

앞의 이동 불가 6개와 조기 복귀 3개는 당시 제시된 다른 이동을 고르면 해결할 수 있었다. 9개의 미루기는 ‘해결 가능한 순서를 우선하지 않은 선택’이다. **미루기 자체를 항상 오답으로 취급하지 않는다.** 여러 순서의 탐색 비용이나 속도를 비교하려고 미룰 수도 있다. 하지만 이번 세 실행은 같은 패턴으로 호출 한도를 소진했고 실제 완성 계획은 찾지 못했다.

거리·시간이 없는 KEV 단독도 0/3 미해결이었다. 정보를 추가한 뒤 단독 성공으로 바뀌지 않았으며, 혼합 방식은 같은 종류의 모델 판단 이후 코드가 이어서 해결했다. 혼합 성공을 모델 단독 성과로 세지 않는다.

우회가 있는 별도 한 상황에서는 전후 모두 해결했고 모델 호출이 5→1회로 줄었다. 더 빠른 최종 경로를 얻은 결과는 아니며 반복적인 우수성 근거도 아니다.

## 확인된 현상과 아직 모르는 원인

확인된 현상은 세 가지다.

1. 점유와 막는 관계가 입력에 있어도 막힌 출발을 선택했다.
2. 지금 복귀할 수 있다는 사실과 통과 전에 복귀하면 다시 막힌다는 사실을 일관되게 구분하지 못했다.
3. 두 대가 비켜준 해결 가능 순서까지 도달하고도 다음 이동을 선택하지 않고 미뤘다.

따라서 ‘경로나 가능한 선택이 없어서 못 풀었다’고만 설명할 수 없다. 반면 모델 내부의 이유는 선택 결과만으로 확인할 수 없다. 관계 설명의 길이·표현, 시간 계산과 제약의 우선순위, 후보 이름·순서, 모델 자체의 여러 단계 판단 능력 중 무엇이 원인인지 아직 분리되지 않았다. 특히 작은 최소 예상 시간은 실행 허가가 아니라는 점을 모델이 올바르게 적용했는지 추가 확인할 여지가 있다.

## 설명을 보완해도 계속 못 푼다면

다음 확인은 두 대 모두 비킨 상태처럼 답이 명확한 일부 상태를 짧은 입력으로 분리하는 것이다. 모든 제약을 제거해 쉽게 만든 문제의 성공과 실제 탐색의 성공은 구분한다. 같은 상태를 기존 입력·짧은 표현으로 비교하고, 개선되면 원래 전체 상황에서 같은 한도로 다시 검증해야 한다. **후속 시험은 실행했고 기준 미달로 중단했다.** [짧은 입력 48회 비교와 중단 판정](kev-mapf-concise-probe-20261022.md)을 참조한다. 아래의 권고는 운영 기본값 변경과 구분한다.

그 뒤에도 같은 실패가 남거나 코드보다 해결률·검사량·판단 포함 시간이 나아지지 않으면 다음 원칙을 권한다. 아직 운영 기본값 변경을 수행한 것은 아니다.

- 여러 단계 양보 순서의 필수 판단은 검증된 코드가 맡는다. 검사·시간 한도와 해결 실패 시 출발하지 않는 처리를 유지한다.
- KEV는 실행 가능한 완성 조정안 중 선택하거나, 이점이 확인되는 상황에서만 탐색을 보조하는 역할로 줄여 검증한다. 이미 코드가 가장 좋은 시간을 정확히 계산할 수 있고 모델이 이점을 못 보이면 해당 선택에도 KEV를 넣을 이유는 없다.
- 모델 실패마다 호출 횟수를 계속 늘리거나, 코드가 해결한 결과를 KEV의 성과로 발표하지 않는다.
- 파인튜닝·다른 모델은 별도 대안이다. 실패/성공 학습 자료, 지도·배치가 다른 평가 자료, 필요한 자원과 비교 기준을 먼저 준비해야 한다. 지금 바로 해결된다고 가정하지 않는다.
- ‘현 모델·입력·허용 동작·한도에서 코드 대비 이점이 확인되지 않음’도 유효한 연구 결과다. 모든 MAPF나 모든 AI가 불가능하다는 결론으로 확대하지 않는다.

# 확률 순서 재사용: 새로운 네 장면 비교

2026-10-23. [첫 호출 절감 시험](traffic-strategy-probability-order-20261023.md) 뒤 사용자 승인으로 추가한 비교다. 기존 시험·결과와 일반 주문의 판단기는 유지한다.

## 확인할 질문

같은 상태의 후보별 확률 순서를 재사용하면 매번 질문하는 방식보다 호출을 줄일 수 있다. 하지만 같은 지점에서 나온 새로운 실패 이유를 그 지점의 순서에 반영하지 않는다. **새로운 상황에서도 해결 여부·계획 품질을 유지하며 판단 비용을 줄이는가?**를 확인한다.

## 모델 시험 전에 고정한 네 장면

| 장면 | 출발 → 이번 목적지 | 살펴볼 점 |
| --- | --- | --- |
| 자기 홈으로 복귀 | R1 N3→N0, R2 N4→N1, R3 N6→N2 | 이전 출발 장면과 다른 경로·이동 거리에서도 유지되는가 |
| 요청 순서 반대로 | 위와 같은 위치·목적지. 입력 순서만 R3→R2→R1 | 요청 순서가 탐색·계획 품질에 미치는 영향 |
| 첫 방법이 막힘 | R1 N4→N5, R2 N12→N6, R3 N2 정차 | R1 기본 경로가 R2에 막힘. R2가 떠나도 목적지 N6가 R1 기본 경로를 막아 우회가 필요 |
| 제한된 우회 | R1 N6→N0, R2 N7 정차, R3 N5 정차 | 아래쪽·중앙 길은 정차 로봇이 막음. N11→N12→N8 쪽 우회 검토 |

복귀 목적지는 각 로봇의 홈 R1=N0, R2=N1, R3=N2로 맞췄다. N6에서의 복귀와 N5·N7 정차 등은 시험을 위해 의도적으로 만든 상태다. 자연스러운 연속 주문에서 이미 관측됐다는 뜻이 아니다. 픽업·ArUco·작업은 실행하지 않는다.

앞 두 장면은 물리적 위치·경로·목적지가 같고 요청 순서만 다르다. 탐색 입력의 요청 순서·선택지 배치가 달라지므로 모델 응답이 반드시 같아야 하는 시험은 아니다. 영향 자체를 기록한다.

모델 호출 전에 공통 A*·코드 탐색으로 네 장면 모두 완성 계획이 있음을 확인한다. 세 번째는 첫 기본 경로가 실제 예약 검사에서 탈락하고 R2 선행·R1 우회로 풀리는지, 네 번째는 두 정차 로봇을 움직이지 않고 우회하는지 확인한다. 이 준비 결과를 전역 최적이나 KEV의 정답이라고 부르지 않는다.

정의: [traffic_strategy_probability_cases.json](../../tests/traffic_strategy_probability_cases.json). 기존 5장면 파일은 변경하지 않는다.

## 공통 실행 조건

- 코드 탐색 / KEV 매번 질문 / KEV 확률 순서 재사용, 장면당 각각 1회. 총 12회.
- 같은 모델·지시문·지도·A*·입력 사본·예약 검사·가상 실행기. 정지 상태, 활성 예약 없음, 한 대씩 목적지까지 이동. 정차 로봇 양보는 허용하지 않는다.
- `equal_time`: 10초, 검사 128회, 우회 생성 16회, 단계 8개, 개별 모델 요청 2초. 총 모델 호출 상한은 없음.
- 실행 순서는 기존 도구처럼 장면마다 순환한다. 준비 호출 1회는 별도 기록한다. 서버 부하·실제 물류 처리량 시험은 아니다.
- 기존 KEV가 완료한 장면을 재사용 방식이 놓치거나 선택 계획의 예상 평균 도착 시간이 더 커지면, 호출 감소만 보고 채택하지 않는다. 차이를 먼저 보고하고 일반 주문 연결을 진행하지 않는다. 시간 차이는 계산값으로 비교하되 1e-6초 이하 차이는 부동소수점 오차로 취급한다.
- 모두 유지하더라도 한 번씩의 제한된 장면 시험이다. 다음 일반 주문 검증은 별도 단계이며 기본 판단기를 자동 교체하지 않는다.

```bash
cd ~/dev/Logistics_AI
PYTHONNOUSERSITE=1 ~/venv/robot/bin/python \
  -m backend.simulation.traffic_strategy_comparison \
  --catalog tests/traffic_strategy_probability_cases.json \
  --comparison repeat_vs_rank --profile equal_time --run \
  --host http://127.0.0.1:8012 \
  --output logs/traffic-strategy-comparisons/새로운-네장면-비교폴더
```

실제 모델을 쓰기 전에는 `--run`을 빼 코드 준비 검사만 실행한다. 결과 폴더는 덮어쓰지 않는다. 실패하거나 불리한 결과가 나와도 입력·지시문을 고쳐 반복 시험하지 않고 보존한다.

### 실패 뒤의 동작도 확인했나

세 번째 장면에서 R1의 기본 경로는 N12의 R2 때문에 검사에서 탈락했다. 유효한 완성 계획은 **R2 N12→N11→N6 이동 → R1 N4→N12→N11→N7→N5 우회**였다. R2가 도착해 점유한 N6를 R1이 피한다. 두 KEV 방식 모두 같은 계획을 찾았다.

네 번째는 **R1 N6→N11→N12→N8→N10→N0**로 우회했다. 정차한 R2=N7, R3=N5는 움직이지 않았다. 길이 막혔다는 이유로 임의 양보 이동을 추가한 것이 아니다.

이번 장면에서는 같은 지점의 실패 뒤 다시 묻지 않아도 해결할 수 있었다. 다른 실패에서 피드백 생략이 항상 괜찮다는 보장은 아니다.

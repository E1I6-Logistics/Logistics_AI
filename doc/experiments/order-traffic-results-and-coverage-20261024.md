# 주문 시험의 범위와 KEV 비교 결과 모음

2026-10-24. A·B 집중 시험까지 저장된 결과를 다시 읽어 정리했다. 이번 정리에서는 서버 시작·새 주문·모델 호출을 하지 않았다. 기존 실행 원문은 수정하지 않았다.

## 먼저 바로잡을 점: 12건이면 모든 것을 검증하는가

**아니다. 12건은 한 상황에서 주문 처리 흐름을 확인하기 위해 선택한 짧은 시험 길이다. 모든 상황을 검증하기에 충분한 수라는 뜻이 아니다.**

주문표에 넣을 수 있는 것과 실행 중 실제로 발생해야 하는 일을 구분한다.

| 구분 | 예 | 주문표 12건만 정하면 보장되는가 |
| --- | --- | --- |
| 주문의 종류 | A/B만, C/D만, 두 픽업대 모두 방문 | 구성할 수 있음 |
| 입력 경계 | 1개 주문, 최대 적재량 5개 주문 | 구성할 수 있음 |
| 접수 방식 | 처음 여러 건, 일정 간격 추가, 중간에 한꺼번에 추가 | 접수 시각표로 정할 수 있음 |
| 교통 상황 | 세 로봇이 같은 길목을 요청, 기본 경로가 막혀 우회 필요 | 주문표만으로 항상 발생한다고 보장할 수 없음 |
| 운영 예외 | 픽업 작업 지연, 통로가 막혔다가 열림, 모델 응답 실패 | 별도 초기 상태·지연·장애 조건이 필요 |
| 오래 운용할 때의 문제 | 특정 주문이 계속 밀림, 지속 처리량, 드문 실패 | 짧은 12건 한 번으로 확인할 수 없음 |

예를 들어 A/B 전용 4건·C/D 전용 4건·두 픽업대 방문 4건으로 기본 주문표를 구성하면 세 방문 유형을 두루 포함할 수 있다. 이것은 지난 보통 접수·폭증 시험의 구성이다. 그러나 C/D 전용 4건이 중간에 들어 있는 것과 12건 모두 C/D로 몰리는 것은 서로 다른 부하다. 모든 종류를 조금씩 넣은 한 주문표가 모든 집중 상황을 대신하지 못한다.

또한 품목·수량 조합이 달라도 이동 경로는 같을 수 있다. 현재 시뮬 작업 시간은 수량과 무관하게 1.5초다. 수량 1개와 5개를 넣는 것은 주문 입력·적재 제한을 확인하지만, 실제 다섯 번 집는 작업 부하를 재현하는 것은 아니다.

### 권하는 구성

1. **기본 주문표 12건:** 방문 유형·입력 경계·반복 배차·픽업·작업대·복귀를 두루 확인한다.
2. **집중·지연 시험:** A/B 집중, C/D 집중, 작업 지연처럼 확인하려는 상황을 각각 분리한다. 하나에 섞으면 원인이 흐려지고 집중 부하가 약해질 수 있다.
3. **특정 막힘·오류 장면:** 위치·점유·예약·해제 시점·응답 오류를 고정해 원하는 장면을 만든다. 이런 시험까지 반드시 주문 12건일 필요는 없다.
4. **긴 연속 운행과 반복:** 장기 대기·지속 처리량·속도 차이의 재현성은 별도로 확인한다.

각 시험에는 ‘입력에 무엇을 넣었는가’ 외에 **‘확인하려던 일이 실제로 일어났는가’**도 기록해야 한다. 예를 들어 ‘N5가 비워진 뒤 다음 로봇이 이동했고, 앞 로봇은 아직 작업대 이동 중이었다’처럼 관측 근거를 남긴다. 장면이 발생하지 않았다면 그 항목은 미확인이다.

## 1. 현재 목표에 직접 해당하는 비교: 기존 관제와 우리 방식

비교 대상은 **시뮬·알고리즘의 기존 관제**와 **시뮬·AI에서 A*＋KEV 전략 순서를 사용하는 우리 방식**이다. 기존 알고리즘에도 시간·예약을 고려하는 경로 계산과 교통 제어가 있다. 우리 방식 내부의 코드 선택기를 기존 관제라고 바꾸어 부르지 않는다.

각 행은 같은 주문 내용·접수 계획·지도·초기 로봇·주행 설정을 두 방식으로 한 번씩 실행한 결과다. 행마다 공급 속도·방문 구성·물품 수가 다르므로 서로 다른 행의 절대 시간을 같은 난이도처럼 비교하지 않는다. 평균 주문 시간은 접수 응답부터 작업대 작업 완료를 처음 확인할 때까지이며 홈 복귀는 제외한다.

기존 알고리즘의 모델 요청은 전부 0회다. 위 KEV 호출은 주문 판단에 실제 전송한 요청 수이고 별도 준비 요청은 제외한다.

**6쌍·12회 운행·총 주문 144건·물품 456개를 모두 처리했다.** 두 방식 모두 주문·복귀 실패가 없었고, 최종 3대가 홈에서 IDLE이었다. 점유 표본 7,641회에서 노드·물리 엣지 중복은 관측되지 않았다. 이는 이 표의 선택된 시험 범위에 대한 결과이지, 과거 모든 실험이 성공했다거나 실기체 안전을 입증했다는 뜻은 아니다.

우리 방식이 빠른 경우 2쌍, 느린 경우 4쌍이었다. 이를 일반적인 승률이나 통계적 우열로 해석하지 않는다. **정상 처리 연결은 확인됐고 일관된 속도 개선은 확인되지 않았다.**

## 2. 앞서 했던 우리 흐름 내부의 비교

다음은 위 표의 기존 관제와 다르다. 추가 교통조정 흐름 안에서 코드의 예상 시간 선택과 KEV 전략 순서를 바꾼 시험이다. 각 조건 12건이며 서로 다른 주문표 두 개를 사용했다.

| 상황·주문표 | 내부 코드 선택: 평균 주문 시간 | KEV 전략 순서 | 관측 결과 |

| A/B 집중 42 | 52.97초 | 54.23초 | KEV가 김 |
| A/B 집중 137 | 53.16초 | 54.37초 | KEV가 김 |
| 모든 주문 두 픽업대 방문 42 | 54.38초 | 51.58초 | KEV가 짧음 |
| 모든 주문 두 픽업대 방문 137 | 54.41초 | 50.40초 | KEV가 짧음 |
| 두 픽업대 방문 주문 빠른 공급 42 | 71.21초 | 67.18초 | KEV가 짧음 |

이 시험도 총 144건의 작업·복귀를 완료했다. 위의 두 모드 직접 비교 144건과 **별도의 실행**이다. 혼합·빠른 공급에서 빨랐지만, 저장 기록에서는 6번 주문의 배차 로봇과 출발 위치가 갈라졌다. KEV가 배차를 선택한 것이 아니라 공통 배차 코드가 당시 상태에서 다른 로봇을 선택한 것이다.

KEV 쪽 적용 이동 264회 모두 준비한 전략을 검토했고 최종 선택은 코드의 최소 예상 시간 규칙과 일치했다. 전략 검토를 줄였다는 근거는 없었다. [내부 부하 비교](order-traffic-load-comparison-20261023.md), [배차가 갈라진 시점 분석](order-traffic-load-review-20261023.md).

### 빠른 결과가 KEV의 판단 덕분인지 확인한 대조

같은 새 전략 흐름에 12건·41개를 넣고 다음 세 조건을 비교했다.

| 순서를 정하는 방법 | 평균 주문 시간 | 실제 모델 요청 |
| --- | ---: | ---: |
| 실제 KEV | 50.48초 | 19회 |
| 코드의 고정 순서 | 54.15초 | 0회 |
| 같은 고정 순서＋짧은 인공 대기 | 50.37초 | 0회 |

**모델 없이 짧은 대기만 넣어도 비슷한 빠른 흐름이 나왔다.** 따라서 앞선 빠른 결과를 ‘KEV가 더 좋은 전략을 골랐기 때문’이라고 설명할 수 없다. 짧은 대기는 원인 확인용 실험이며 운영에 추가하지 않았다. 반복이나 요청별 지연을 정확히 일치시킨 인과 실험은 아니므로, 지연 하나가 모든 차이의 원인이라고 확정하지도 않는다. [응답 대기 대조](order-traffic-ranking-ablation-20261023.md).

| A/B 집중과 C/D 집중이 각각 문제없음 | A/B만 직접 비교 완료. C/D 집중은 별도 확인 필요 |
| 픽업·작업 시간이 길어지는 부하에서도 동일하게 처리 | 위 표의 두 모드 비교는 공통 1.5초이며 지연 부하는 아직 아님 |
| 막힘·일시 점유·우회가 필요한 장면을 현재 일반 주문에서 모두 비교 | 별도 장면 시험과 구분해야 함. 주문표에 섞는 것만으로 모든 장면 발생을 보장하지 못함 |
| KEV가 준비 전략의 검토 수를 줄임 | 최근 일반 주문 결과에서는 확인하지 못함 |
| KEV가 일관되게 더 빠르고 지속 처리량이 높음 | 미확인 |
| 긴 연속 운행·4대 이상·실기체에서 같은 결과 | 이 결과만으로 확인 불가 |

**지금의 결론은 ‘연결해서 동작시킬 수 있다’는 근거는 있고, ‘KEV를 넣어서 좋아졌다’는 근거는 아직 부족하다는 것이다.** 둘을 분리해야 한다. 새 상황을 조금 더 확인하는 일과 같은 조건을 반복해 우열을 판단하는 일도 다르다.

다음 기능 확인은 C/D 집중, 이후 작업 지연 또는 일시 점유·해제처럼 목적이 분명한 상황이 적절하다. 장기 운용을 검증할 때는 공급 기간과 공급 종료 후 해소를 나누고, 속도 우위를 주장하기 전에는 부하가 적은 상태에서 동일 조건을 반복한다. 이번 정리에서 새 시험을 시작하거나 주문표를 수정하지는 않았다.

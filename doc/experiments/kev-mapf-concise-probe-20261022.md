# 짧게 설명해도 KEV가 양보 순서를 고르는가: 기준 미달로 중단

2026-10-22. [저장된 실패 기록 분석](kev-mapf-motion-answer-analysis-20261022.md) 후 사용자가 정한 범위 안에서 입력 표현을 비교했다. **모델 요청 48회 후 사전 기준 미달로 중단**했다. 허용 상한 192회를 채우지 않았으며 후속 전체 이동 시험도 실행하지 않았다. 일반 주문·실기체에 명령을 보내거나 운영 설정을 변경하지 않았다.

## 미리 정한 진행·중단 기준

4개 상태 × 기존/짧은 설명 × 선택지 정순/역순 × 3회 반복 = 48회다.

1. 출발 전: R2·R3가 R1의 길을 막고 있다.
2. 한 대 양보 후: R3가 N8로 비켰고 R2는 N11을 막고 있다.
3. 두 대 양보 후: R2·R3가 모두 비켜 R1의 경로가 비었다.
4. R1 통과 후: R1이 N0에 도착했고 지원 로봇들이 돌아가야 한다.

첫 세 상태가 핵심 기준이다. 짧은 설명에서 각각 **6회 중 5회 이상** 해결로 이어지는 이동을 고르고, 전체 정답 수가 기존보다 줄지 않아야 다음 전체 시험으로 넘어가기로 했다. 후속 시험은 코드/기존 KEV/짧은 설명 KEV를 같은 세 상황에서 비교할 계획이었으나 첫 기준을 통과하지 못해 실행하지 않았다.

이 기준은 이번 구조의 개발을 계속할지 판단하는 예비 기준이다. 6회 반복을 서로 다른 상황 6개나 통계적 일반 성능 증명으로 취급하지 않는다. 지시문을 반복 수정하면서 이 시험에만 맞추지도 않았다.

## 무엇을 짧게 바꿨나

기존 입력은 각 이동의 경로·점유·길막 관계·시간 수치를 상태와 선택지에 중복해서 담는다. 새 표현은 **상태 안의 중복 이동 설명만 제거**하고 같은 내용을 모든 선택지에 그대로 유지한다. 로봇 정보·남은 경로·관계·시간 수치·차단 제약·계획 기록과 후보 집합은 보존한다. 후보를 미리 제거하거나 완성 정답을 알려주지 않았다.

지시문도 한국어로 줄여 다음 규칙을 분명히 적었다.

> 길을 비운 뒤 통과하고, 통과 전에 길을 다시 막는 복귀를 하지 않는다. 유용한 이동이 남으면 진행한다. 되돌릴 수 없는 막힘이나 모든 후보가 막힌 경우에 현재 순서를 미룬다. 시간 값보다 이 제약을 우선한다.

평균 시간은 원래 이동 요청만 세며 낙관적인 계산이라는 설명, 예약 검사는 코드가 담당한다는 조건도 유지했다. 후보 ID에 정답 의미를 붙이지 않았다.

**중복 제거·지시문 표현·언어를 함께 바꾼 비교**다. 결과를 입력 길이 하나의 효과나 언어 하나의 효과로 분리해서 해석할 수 없다. 운영 입력 형식을 바꾸지 않는 별도 선택기 래퍼로만 수행했다.

## 결과

실제 모델은 `jaredpalmer/kev-0.8b@v1.0`이다. 48회 모두 정상 응답했고 응답에 입력 잘림 표시가 보고되지는 않았다. 이것만으로 모델이 모든 사실을 정확히 활용했다는 뜻은 아니다.

| 상태 | 기존 설명 | 짧은 설명 | 짧은 설명의 기준 |
| --- | ---: | ---: | --- |
| 출발 전 | 3/6 | 3/6 | 미달 |
| 한 대 양보 후 | 0/6 | 3/6 | 미달 |
| 두 대 양보 후 | 0/6 | 0/6 | 미달 |
| R1 통과 후 | 0/6 | 0/6 | 보조 확인에서도 미선택 |
| 전체 | 3/24 | 6/24 | 핵심 상태별 기준 미달 |

‘맞힘’은 **그 이동을 고른 뒤 이번 시험의 허용 경로와 로봇당 양보 1회·최대 8단계 안에서 모든 도착·복귀를 끝낼 수 있는 순서가 존재함**을 뜻한다. 가장 빠른 전체 계획을 골랐다는 뜻이 아니다. 미루기는 즉시 해결로 이어지는 이동을 고른 것으로 세지 않았다.

특히 두 대 모두 비킨 상태에서는 R1 출발이라는 해결 가능한 선택지가 있는데도 두 표현 모두 6회 전부 `BACKTRACK`을 골랐다. R1 통과 후에도 복귀 대신 같은 미루기를 선택했다. 이는 계획 안의 선택이며 실제 로봇을 후진시킨 것은 아니다.

선택지 순서 영향도 남아 있다.

| 상태·표현 | 정순에서 맞힘 | 역순에서 맞힘 |
| --- | ---: | ---: |
| 출발 전·기존 | 0/3 | 3/3 |
| 출발 전·짧은 설명 | 3/3 | 0/3 |
| 한 대 양보 후·짧은 설명 | 3/3 | 0/3 |

같은 상태에서 순서에 따라 결과가 바뀌므로 3/6을 안정적인 이해의 증거로 삼기 어렵다. 평균 입력 토큰은 약 2,588→1,754, 평균 요청 시간은 약 0.183→0.143초로 줄었지만 **응답이 빨라진 것과 문제를 해결한 것은 다르다.** 고정 상태 질문의 응답 시간을 일반 주문 처리 시간으로 해석하지 않는다.

## 결론과 권고 범위

**현재 KEV 0.8B·이번 입력·설정에서 다중 양보의 다음 행동 판단은 실용 수준에 도달하지 못했다.** 원래 전체 시험도 0/3이고 짧은 상태 시험도 기준 미달이므로, 지시문을 더 바꾸거나 호출 한도를 늘리는 확장은 여기서 중단할 근거가 있다.

모델 내부 원인은 확인하지 못했다. KEV 전체·모든 모델·모든 MAPF가 불가능하다는 결론이 아니다. 다른 체크포인트·학습·입력 설계가 개선될 가능성과 현재 구조에서의 실용성은 별개다.

현재 추천은 다음과 같다. **아래는 향후 진행 권고이며 운영 설정을 변경한 것이 아니다.**

- 실제 교통조정의 다중 양보 순서는 검증된 코드 방식으로 안정성을 확보한다. 예약·점유 검사와 실패 시 무출발을 유지한다.
- KEV 방식은 비교 시험으로 보존하고, 여러 단계 순서 결정을 더 넓게 맡기는 작업은 중단한다. 코드가 해결한 결과를 KEV의 성과로 발표하지 않는다.
- 기존 일반 주문의 ‘검사된 완성 조정안 중 선택’과 이번 ‘다음 검사 동작부터 선택’은 다른 역할이다. 이번 결과만으로 기존 역할 전체를 실패 판정하거나 운영에서 일괄 제거하지 않는다. 그렇다고 기존 역할의 성능 우수성이 자동으로 입증된 것도 아니다.
- 모델의 새 기여가 꼭 필요하면 학습 자료·다른 배치의 평가 자료와 별도 실험 예산을 먼저 정한다. 파인튜닝이나 큰 모델을 바로 도입하면 해결된다고 가정하지 않는다.
- 다음 개발은 기능 배치보다 연속 주문에서의 완료·막힘·예약 위반·취소 후 복구 등 동작 안정성을 우선한다. 일반 주문에 새 다중 양보를 연결할지는 영향 범위를 따로 설계한다.

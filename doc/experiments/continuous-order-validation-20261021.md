# 일반 주문 18건씩 연속 처리 검증

2026-10-21. **KEV 선택과 코드 선택 모두 18건·57개 물품을 끝까지 처리했다.** 총 36건·114개이며 주문 실패·취소·복귀 오류가 없었다. 이번 한 쌍에서 코드는 약 3.35초 빨랐다. 작은 반복 표본이므로 일반적인 성능 우열을 확정하지 않는다.

## 이번에 확인한 흐름

```text
일반 주문 API에 계속 등록
 → 배차 대기열
 → 가용 로봇에 배차
 → A*로 이번 목적지 경로 생성
 → 기존 점유·예약을 고려한 경로 후보 생성·검사
 → 후보가 여러 개일 때 KEV 또는 예상 시간 최소 코드로 선택
 → 최신 상태 재검사·이동
 → 픽업·작업대 작업·다음 주문 또는 복귀
```

이것은 일반 주문에 이미 연결된 **새 이동 요청의 경로 후보 선택** 검증이다. [별도 다중 양보 시험의 KEV 추천·코드 보완](deferred-recovery-20261020.md)과 적용 범위가 다르다. 일반 주문의 여러 주행 계획을 새 다중 양보 방식으로 교체하지 않았다.

주문 처리·배차·경로 생성·교통조정 코드는 수정하지 않고 기존 관제와 실행·관측기를 재사용했다. 현재 흐름에서 연속 처리가 되는지 실제 가상 로봇 상태로 확인했다.

## 비교 조건

- seed `20261021`의 동일한 주문 18건·57개. 한 주문의 물품 합계는 1~5개다.
- 7건은 픽업대 한 곳, 11건은 OMX1·OMX2 두 곳을 방문한다. 현재 방문 순서를 유지했다.
- 처음 3건을 등록하고 이후 5초마다 한 건씩, 75초까지 공급했다. 두 실행의 주문표 해시가 같다.
- 동일 지도, 같은 시작 위치·자세·배터리, 같은 시뮬·AI 모드, A* 경로 생성과 기존 가상 주행 속도를 사용했다.
- 시작 위치는 대기 노드 N0·N1·N2로 동일하게 맞췄다. 직전 다중 양보 시험의 위치 N0·N11·N10은 원본 상태에 보관하고 종료 후 복원했다.
- 후보 생성·예약 검사·배차 정책은 같고 선택만 `KEV`와 `MIN_EXPECTED_TIME`으로 바꿨다. 후보가 하나면 둘 다 모델을 호출하지 않는다.
- 실제 등록 지연은 목표 시각에서 최대 약 0.20초·0.21초였다.
- KEV → 코드 순으로 한 번씩 실행했다. 순서 효과·반복 변동까지 분리한 통계 실험은 아니다.

공급 시각을 같게 유지하려고 이 비교에는 대기열 상한을 적용하지 않았다. 화면의 **연속 주문 · AI 자동 공급 / 시작·중지**는 기존대로 최초 3건·5초 간격·PENDING 상한 3건을 사용한다. 그 설정은 변경하지 않았다.

## 물류 흐름이 이어졌는지 확인한 내용

**앞 주문 전체가 끝나기 전에 다음 로봇이 같은 픽업대로 이동했다.** KEV 실행 약 18.29초에 1번 주문의 R1은 작업대로 이동 중이었고, 3번 주문의 R3는 비워진 N5로 이동 중이었다. 실제 엣지 점유와 목적지·예약 적용 기록을 함께 확인했다.

**홈 복귀를 끝내기 전 새 주문을 받은 사례가 있었다.** KEV 실행 약 31.91초에 R3는 3번 주문의 작업대 N4에서 6번 주문을 받았다. 코드 실행에서도 약 31.74초에 같은 전환을 관측했다. 복귀 중 모든 로봇을 항상 재배차한다는 뜻은 아니다. 같은 픽업대의 앞선 요청이 있으면 복귀 로봇을 곧바로 그 대기열에 넣지 않는 현재 규칙을 유지했다.

대기 주문이 있으면서 활성 주문이 연결되지 않은 정지·무경로·정지 요청 없는 로봇이 관측된 가장 긴 구간은 양쪽 모두 약 **0.23초**였다. 표본에서는 오랫동안 빈 로봇을 두고 배차하지 않는 현상을 찾지 못했다. 이 계산은 화면 상태로 확인 가능한 조건을 사용한 관측 지표이고, 모든 배차 제한을 재현한 판정기는 아니다.

대기 주문은 양쪽 모두 최대 9건, 진행 주문은 최대 3건이었다. 평균 배차 대기가 약 40초인 것은 배차 확인 주기가 40초라는 뜻이 아니다. 공급을 먼저 끝내고도 남은 주문이 대기열에서 차례를 기다린 것이다. 이 PENDING 대기는 경로 예약을 찾는 60초 상한과 별개다.

관측 구간별 주문 상태의 시간을 합산하면 KEV 실행의 PENDING은 약 736.69 주문·초, WAITING_PICKUP은 약 43.71 주문·초였다. 코드 실행은 약 717.90, 41.83 주문·초였다. 여러 주문의 시간을 더한 값이므로 실제 경과 시간과 직접 비교하지 않는다.

- 총 36건 모두 작업·복귀까지 완료. 실패·취소·복귀 오류 0건.
- 로봇 점유 관측 총 **1,756회**, 노드·물리 엣지 중복 점유 관측 0회.
